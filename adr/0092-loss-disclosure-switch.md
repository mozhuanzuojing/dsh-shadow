# ADR-0092: 召回路径的省略披露做成默认开关（`recall.lossDisclosure`）

- 状态：**已接受**（2026-09-15 / `v1.15.91`）
- 关联 ADR：**ADR-0090**（甲-1：有损必须声明损失形态 + 交出恢复句柄 —— 本条是它的**成本侧**调节）·
  **ADR-0088**（v1.15.85「默认全开」：默认值的判据收一处 `onByDefault`）·
  **ADR-0085**（§5：**用户显式关掉不留痕** —— 关掉是用户的选择，渲染成告警＝把读者的决定当故障）

## Context

`adr/0090` 的 §负/已知边界 自己记下了一条：召回路径的省略披露**有固定成本**（存在「本该有片段却被省略」的条目时，
输出多两行、约 150–250 字），并把它列为**未做**，理由是「取舍应显式写进 README 的默认开关表，而不是悄悄去掉披露」。
用户 2026-09-15 选中了这一条 ⇒ 本轮把它做成开关。

## Decision

- **键名**：`recall.lossDisclosure`（`core/types.ts` 的 `recall` 段内，扁平布尔，与同段的 `debug` 同形）。
- **默认 = 开**。判据**只有一处**：`core/util.ts` 的 `onByDefault`（`undefined` = 开，**只有显式 `false`** 才关），
  与 v1.15.85 的三个量控开关**共用同一份判据**（`adr/0088` 立的规）。
  **为什么默认开而不是关**：`adr/0090` 甲-1 的完成判据是「读侧能区分『无内容』与『被省略』」；
  **默认值就是产品**——默认关等于默认放弃该判据（与 v1.15.85 同一条理由）。要放弃的人**显式关**。
- **关掉的语义边界（本 ADR 最要紧的一句）**：**只改「说了什么」，不改「给了什么」**。
  降档与丢条目的判据（`adr/0090` 的「无句柄不许降档」「降档必须真省字」）**与开关无关**；
  关掉后返回的**条目标识与内容逐字不变**，只是不再出现 `> 分层省略：` 那两行。
  ⇒ 这条**做成了断言**（`test/recall-envelope.test.ts` ⑦：两侧的 `[.shadow/…]` 条目标识序列必须**逐字相同**，
  且关闭侧更短）。否则「关掉省 token」会悄悄演化成「关掉就多给内容」= 用开关绕开预算。
- **范围**：只覆盖**召回路径**的那两行。**索引路径**（`renderIndexBudgeted` 的「未返回的内容 / 未返回的段」）
  **不在本开关范围** —— 它是 v1.15.85 预算信封的一部分，是「整篇 2199 KB 被截断」的**唯一**出口；
  把它也做成开关等于允许「静默截断整篇索引」。

## Alternatives Considered

| 备选 | 否决理由 |
|---|---|
| 默认**关**（省 token 优先） | 默认值即产品：等于默认放弃甲-1 的判据；而该判据正是本轮（v1.15.89）刚立的 |
| 按阈值触发（如「被省略 ≥ 3 条才披露」） | 需要先定**阈值口径**且没有任何证据表明它更优；更重要的是它把「有没有披露」变成**内容相关**，读者更难推理。**登记为将来可选**，不实装 |
| 把索引路径的披露也纳入同一开关 | 见 §Decision 的范围一条：那是唯一出口，不许可关 |
| 关掉后改为「逐条在记忆行尾加一个小标记」 | 改成 O(条数) 成本，比现状更贵；且与本仓「披露收在信封一处」的口径冲突 |

## Consequences

### 正

- 成本**可见且可控**：README 默认开关表多一行（19 行），默认行为不变（开着），要省的人有一条**显式**路径。
- 「开关只改披露、不改内容」是**可测的**，不是承诺 —— 断言钉在 ⑦ 里。

### 负 / 已知边界

- **成本仍在**（默认就是多 150–250 字/次）；本条只给它一个出口，没有把它变小。
- **关掉后 `adr/0090` 甲-1 的判据失效**（读侧无法区分「本来就短」与「被省略」）—— 这是**用户显式选择**，
  按 `adr/0085` 的裁定**不留痕**（不渲染告警）。
- **按阈值触发未做**（见 Alternatives 第 2 条）。
