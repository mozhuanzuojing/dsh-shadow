# ADR-0066: D5 定稿 —— 「会话元数据」判据收敛，修掉两条读路径 66.9% 的可见性分歧

- 状态：**已接受（2026-09-11，由用户「按推荐」授权落地）**
- 决定日期：2026-09-11
- 关联 ADR：**ADR-0063**（本 ADR 结掉它留的 D5 决策项）、ADR-0044/0045/0046（Evidence Gate 与 Lineage Validator）、ADR-0003（Derived Artifact）、ADR-0062（接线审计工具，本轮的线索来源）
- 关联待办：`../BACKLOG.md` 的 **D5（本 ADR 结案）**、T1/T4
- 版本：`1.15.23`

## Context

ADR-0063 用真语料量出：主题召回路径（`query/query.ts:263-296`，**不做 kind 过滤**）看得见 **100%** 的库，
而 `shadow_query` 路径（`deriveShadowNodes` → `validateAtomProjection`）只看得见 **32.8%**
—— **同一份语料，两条读路径可见性相差 67.2%**。根因是 `deriveAtomKind` 拿
`entry === "shadow"`（**写侧兜底字面量**，语义是「没识别出组件」）当「会话元数据」的代理。

ADR-0063 把处置升为 **D5**（三条路）并**明确不擅自改行为**。本轮用户授权「按推荐」，
按 ADR-0063 的建议**先做信号实验**（因为改的是召回语义，不能拍脑袋）。

## Decision

### 1. 信号实验（先测量，再决策）

新增探针 `_research/d5-signal-experiment.ts`，在真 `.shadow` 语料（**7089 条**）上比较 5 个候选判准。
指标：**精度** = 1 −（被判 metadata 中「其实有工作痕迹」的占比）。
工作痕迹 = **有动作行或思维行**（真的干活了）。

> **探针自身的一处缺陷（自曝）**：第一版把「用户话」也算成工作痕迹，
> 而「会话元数据」的语义恰是「**有用户要点、但没有实际工作**」—— 判准因此自相矛盾，
> S4（按定义必须含用户话）的精度**恒为 0%**，读数无意义。已修正指标并重跑。
> （本仓纪律：先证工具，再用工具。不修正就会得出「文档化的定义是错的」这一相反结论。）

**实测结果（7089 条）**：

| 判准 | 判 metadata | 其中**其实有工作痕迹** | **精度** | 挡住投影 |
|---|---|---|---|---|
| **S0 旧（现行）**：`!materials && (entry==="shadow" \|\| userMessages.length)` | 4744 | **4279** | **9.8%** | **66.9%** |
| S1 `!materials && !decisions && !goal && 0 动作` | 1379 | 1050 | 23.9% | 19.5% |
| S2 S1 且无用户话 | 1288 | 1050 | 18.5% | 18.2% |
| S3 旧判准 且 0 动作 | 1662 | 1197 | 28.0% | 23.4% |
| **S4 文本启发式口径**（`entry=shadow && 有用户要点 && !materials && !decisions`） | **93** | **0** | **100.0%** | **1.3%** |

⇒ **S4 是唯一达到 100% 精度的判准**，而它**恰好就是仓库里已经文档化、但从未接线的那一个**
（`isMetadataMemoryText`，ADR-0063 记的「零调用点」函数之一）。

### 2. 决定：判据收敛到 `isSessionMetadataAtom`（唯一判据源）

在 `core/episode.ts` 新增导出：

```ts
export const isSessionMetadataAtom = (p: { entry; materials; decisions; userMessages }): boolean =>
  p.entry === "shadow" && p.userMessages.length > 0 && !p.materials.length && !p.decisions.length;
```

- `deriveAtomKind` 改用它（替换旧判准的第 4 行）。
- `isMetadataMemoryText` **保留**（它服务**不 parseMemory** 的读路径），并注明它是同一判据在
  **文本表面**的等价表达。
- **`isCognitiveAtom` 删除**：它的规则（`kind !== "metadata" && kind !== "session"`）与
  `validateAtomProjection` **完全重复**，且零调用点。三份实现减为两份（两类表面各一份），
  再减为**一个判据源 + 一个文本投影**。

> 删除理由不是「死代码」，而是**消除第三份口径** —— ADR-0063 的病根就是「同一条规则三份实现、
> 口径互不相同」。留着它，下一个人还会写第四份。

### 3. 实测效果（真语料 7111 条，改动前后对照）

| 读数 | 改动前 | 改动后 |
|---|---|---|
| `kind === "metadata"` | 4137（59.4%） | **90（1.3%）** |
| `deriveShadowNodes` 产出 | 2283（32.8%） | **6478（91.1%）** |
| 两条读路径可见性差 | **67.2%** | **8.9%** |
| 残余被拒原因 | metadata 门为主 | **540 证据门 + 90 metadata 门** |

**残余 8.9% 的构成已核实**（探针 `_research/gate-reason-breakdown.ts`）：
`540` 条来自**证据门**（`decision 无 evidence 不进入 context`）—— 那是 ADR-0044/0045 的
**正当拒绝**（「决策发生过 ≠ 决策可靠」），**不是缺陷**；`90` 条来自已校准的 metadata 门（全部真是会话元数据）。

⇒ **分歧从 67.2% 降到 8.9%，且降下去的 8.9% 全部是有据的**。

### 4. 两条实测得出的**边界**（写进测试，防以后有人误判）

1. **`kind === "metadata"` 与判据是「有向」关系，不是等价**：
   `task` 分支（`/todo|plan|待办|任务|…/`，且它扫 `entry + materials + userMessages + goal` 拼成的文本）
   **优先于** metadata 分支。故「用户只说了句『记下待办』」的记忆判 `task` 而非 `metadata`。
   **不影响可见性**（`task` 不被门挡），且语义更准。但必须钉住，否则会被误当等价。
2. **两个口径读的不是同一个表面**：`isMetadataMemoryText` 读**线索头** `> 用户要点：`；
   `parseMemory.userMessages` 读**正文行** `- [..] 用户：…`。真记忆**两者都写**
   （`buildClueHeader` 写头 + trace 写正文）⇒ 真语料上一致；只写头不写正文的文本会分叉。
   这是**已知边界**，在真语料上不出现，测试里显式钉住并断言其分叉。

## Alternatives Considered

| 备选 | 否决理由 |
|---|---|
| **不测量，直接按「看起来更严」的判准改**（如 S1/S3） | 实测 S1/S3 精度仅 **23.9% / 28.0%** —— 它们把大量「有思维行但无动作」的记忆也判成元数据，是**另一种形式的低估**。没有测量就选不出来 |
| 选 S4 之外「更宽」的判准 | 精度是唯一目标是错的；但**放宽必须换来精度**。S4 宽度 1.3% 遮挡、精度 100%，已是最优点；更宽（S1/S3）精度掉到 20% 档，不划算 |
| 采信第一版探针的结论（S4 精度 0%） | 那是**探针指标的错**，不是判据的错。自曝并修正后结论完全反转 —— 这正是「先证工具」的价值 |
| 顺手改 `task` 分支顺序，让 metadata 优先 | 会改动大量 task 记忆的分类，且**不影响可见性**（task 不被门挡）。**不必要的语义震荡**，不做 |
| 把 `isCognitiveAtom` 接到投影路径（而非删除） | 会变成两份 kind 口径同时生效，正是要消除的病根 |
| 保留 `isCognitiveAtom` 只加注释 | 注释挡不住第四份实现的产生。本仓已有三份的教训，**删掉才是收敛** |

## Consequences

### 正
- **两条读路径的可见性分歧从 67.2% 收敛到 8.9%**，且剩余的 8.9% 全部由**有据的证据门**造成。
  ——直接服务本目标的第 (4) 条：**「可供 agent 执行的真相」不能一个入口看得见、另一个看不见**。
- **一个判据源 + 一个文本投影**，替代原先三份口径互不相同的实现。
- 判据的**精度有了可复现的数字**（100% / 1.3% / 7089 条），而不是「看起来合理」。
- 新增的 `test/atom-kind-gate.test.ts` 锁的是**不变量**（两份口径同答、可达性、有向绑定、
  两层边界），不再是「某一次的读数」——ADR-0063 那份决策锁已随 D5 落地**改写成不变量锁**。
- 两处探针缺陷（指标错、分支优先级误判为等价）**都在过程中自曝并记录**，可追溯。

### 负 / 已知边界
- **这是一次召回面变更**：`shadow_query` 的候选从 32.8% 扩大到 91.1%。
  候选变多但输出仍受 `limit`（默认 8）与 AND 匹配约束 ⇒ 影响是「能搜到的东西多了」，
  不是「每次返回更多」。**但这是行为变更，已在此显式记录**（本仓纪律：不静默改行为）。
- **`task` 分支优先于 metadata**（Decision §4.1）—— 保留，不修。
- **头口径 vs 正文口径的表层差异**（§4.2）—— 保留，真语料不触发。
- 残留 `630` 条只在主题召回可见（8.9%）—— 其中 `540` 是**证据门的有意拒绝**，
  不是待修缺陷；若将来要让它们也进上下文，那是**改证据门**（ADR-0044/0045）的独立决策。
- 探针依赖真 `.shadow` 语料，**不在单元测试内**（测试不许依赖机器状态）；语料增长后读数会变。
