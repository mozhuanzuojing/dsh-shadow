# ADR-0073: 重点材料 hl_mem —— 对标结果（可借鉴项 / 不吸收项 / 许可边界）

- 状态：**已接受（2026-09-11）**
- 决定日期：2026-09-11
- 关联 ADR：ADR-0001（自建投影文件树 —— 本 ADR 复用其否决判据）、ADR-0031（`Forget ≠ Delete`）、ADR-0042 / 0043 / 0051（纯函数派生 / LLM 不能制造关系）、ADR-0049（缺件不静默 —— 与其「降级行为」列同向）、ADR-0060（多粒度检索层形态）、ADR-0065（吸收 OpenViking —— **本 ADR 沿用其体例**）

## Context

用户 2026-09-11 两条指令：① 「dsh-shadow 插件 添加参考资料 `github.com/lohr13/hl_mem`」；
② 随后「**把这个作为重点材料**」。经确认，落地为「立 ADR + 记 BACKLOG + 补 CHANGELOG」。

对象：**HL-Mem**（`lohr13/hl_mem`），pyproject 自述 `Evidence-aware local memory service`，
README 定位句为「面向 AI Agent 的**证据驱动长期记忆系统**」——把不可变 Event 经 LLM 提成结构化 Claim，
SQLite 作权威源，FTS + 向量混合召回，经 REST / MCP / Hermes 交给 agent。

**证据来源**（全部一手 raw 文件，抓取 2026-09-11）：GitHub API、`README.md`、`docs/architecture.md`、
`docs/capability-matrix.md`、`docs/adr/0001-core-strategy.md`、`docs/adr/0002-mvp-scope-and-embedding.md`、
`docs/mcp.md`、`docs/archive/research/competitor-comparison.md`、`pyproject.toml`、`LICENSE`。
**未克隆、未运行、未试装；未复现其评测分数。**

**与 ADR-0065 的关系（须先分清）**：0065 处理的是**已决定吸收**的对象（OpenViking）；本 ADR 处理的是
**用户定为重点材料**的对象。**「重点材料」≠「已吸收」** —— 本 ADR 的产出是「标定 + 对标结论 + 可借鉴项清单」，
**不含任何代码或行为改动**。

## Decision

### 1. 先记事实（可复核）

| 项 | 读数 |
|---|---|
| 许可 | **Apache-2.0**（依据：GitHub API `license.spdx_id` + `pyproject.toml` 的 `license = "Apache-2.0"`；**其 `LICENSE` 原文未逐字读取**） |
| 语言 / 运行 | Python **3.12+**（`requires-python = ">=3.12"`；权威 CI 只在 3.13） |
| 版本 / 活跃 | 最新 release **v1.1.7**（2026-09-08）；创建 2026-07-19；最近推送 2026-09-08 |
| 规模 / 维护 | **7** ⭐ / 0 fork / 5 open issues；`main` **983** 提交；contributors API 仅 1 人（`lohr13`） |
| 依赖形态 | `fastapi` / `uvicorn` / `numpy` / `pydantic` / `jieba` / `httpx`；可选 `mcp`、`sqlite-vec` |
| 接口 | CLI（`hlmem`）/ FastAPI REST / **MCP stdio**（7 工具）/ Hermes Provider |
| 存储 | SQLite WAL + FTS5 + 向量 BLOB（`sqlite_scan` 默认，可显式换 `sqlite_vec`） |
| 目录规模 | tree **1110** 条目；`docs/superpowers/plans/` 20+ 篇计划留档；`benchmarks/archive/v030/` 整段历史归档 |

**规模判断必须带上**：单人维护 / 7 ⭐ / 983 提交 —— 它的价值在**工程纪律的密度**，不在生态位。
这与 ADR-0065 对 OpenViking（36k ⭐、VLDB 论文）的证据强度**不是一个量级**，下文结论的措辞按此收紧。

### 2. 它真正值得本仓看的：**治理与文档形态**，不是检索算法

本仓检索形态已由 ADR-0060 定形（单索引 + 层级表示 + 路由，不引向量库）。HL-Mem 的检索是
FTS + Dense + RRF + 可选 Reranker —— **与本仓不同路，本 ADR 不主张改**。对照价值集中在三处：

| # | HL-Mem 的形态 | 本仓现状（已核实） | 判断 |
|---|---|---|---|
| ① | `docs/capability-matrix.md`：**逐特性六列** —— 成熟度（stable/beta/experimental）· 默认模式 · 是否调外部 API · 是否写库 · **降级行为** · **晋级标准** | README 有 **「默认开关」表**（`README.md:113-130`，**16 条能力 × 3 列**：能力 / 默认 / 开着会怎样·怎么开）—— **已覆盖**「默认模式」与「怎么开」，**缺**成熟度、**降级行为**、**晋级标准** 三列 | ✅ **可借鉴** → 记 **D8** |
| ② | `docs/adr/0001-core-strategy.md`：「**被放弃的方案**」逐条写「优点是…**放弃原因是**…」，末尾另有「**重新评估条件**」清单 | 本仓 ADR 体例：**既有 ADR（84 个文件）中 34 个带 `## 自检`**（含「未做 / 未验证」两款），**0 个**带「重新评估条件」小节 —— 计数按**本 ADR 引入前**计（否则本 ADR 自己会把两项各 +1） | ⚠ **观察到的差异，本轮不立待办** —— 本仓「自检」的「未做/未验证」已承担同一职能（防「以为做过」）；再加一节属**体例偏好**而非**缺口**（依本仓纪律「宁可少列，不留悬空项」） |
| ③ | `docs/archive/` 分层：完成的提案 / 历史设计 / 旧 release 整体归档，并明写「**不代表当前路线图**，当前行为以 architecture + capability-matrix 为准」 | `docs/` 只有 `toolchain-windows.md` / `toolchain-wsl.md` + archify 产物；**无** archive 分层 | ⚠ **暂不借鉴** —— 本仓等价机制是 `CHANGELOG.md`（逐版留决策）+ `BACKLOG.md`（只登记未完成）；再叠一层 archive 是**重复台账** |

> **一处必须先自我纠正的说法**：本仓**并非「没有能力矩阵」** —— README 的「默认开关」表已经是一张
> 成熟度矩阵的**表头裁剪版**。真实的缺口是**三列**，不是**一张表**。这个精度差异决定了 D8 是「补列」而非「新建」。

### 3. 唯一落地的借鉴项 → D8

**把 README 的「默认开关」表升级为逐能力成熟度矩阵**（补三列：成熟度 / 降级行为 / 晋级标准）。

理由**不是**「它这么做」，而是本仓已有缺口：

- **ADR-0049「缺件不静默」要求降级必须可见**，但该纪律目前**分散在代码注释与 ADR 正文里**
  （如 `toolset` 的 `degradesTo`、`routeVerify` 的 `unavailable`、`recall` 的关键词兜底），
  **没有一处能一眼看全**「每个增强关掉 / 缺件时，行为退到哪」。
- **「晋级标准」**（什么条件下才允许 beta → stable）与 ADR 的「重新评估条件」是**同一诉求**，
  本仓目前只在个别 ADR 里零散出现。

记入 `BACKLOG.md` 的 **D8**（四项格式齐备）。**本轮只登记，不实现。**

### 4. 明确不吸收（逐条给理由）

| 项 | 不吸收的理由 |
|---|---|
| **「LLM 负责提取」的写入路径** | **硬冲突**：本仓铁律是**纯函数派生、不猜字段、LLM 不能制造关系**（ADR-0042 / 0043 / 0051）。它的 Claim 由 LLM 从 Event 提取 ⇒ 与本仓写入路径**不可拼接**。**只取治理与文档形态，不取写入路径。** |
| **常驻服务（FastAPI + worker + 服务化 SQLite）** | **ADR-0001 已否**，判据是「要额外跑一个重服务（DB / RAG），对『agent 缺上下文就去翻』这种低成本诉求过重」。HL-Mem 是**同一判据下的第二个样本** ⇒ 判据复用，结论不变。 |
| **向量库 / 混合检索（FTS + Dense + RRF + Reranker）** | 本仓已按 ADR-0060 定形为「单索引 + 层级 + 路由」，且其实测结论是「**加判别层优先于加库**」。**本 ADR 不主张改检索形态。** |
| **物理删除闭包 + tombstone + fail-closed** | 本仓是**有意相反**：`Forget ≠ Delete`（ADR-0031；`core/forget.ts` 文件头注释明写「文件保留，只是不再被索引/召回当作活跃知识扫描」）。改成物理删除会**直接推翻 ADR-0031**。注：本仓源码 `tombstone` **0 命中**（已核实）——**这不是缺口，是设计取向**。 |
| **双时间模型（valid time / recorded time 字段体系）** | 本仓近邻能力是 `asOf`（Observer v2 时间锚定，`core/util.ts:51` 的 `parseAsOf`；落在 `core/types.ts` / `query/query.ts` / `retrieval/render.ts` / `observer/core.ts`）——语义是「**按时间点召回当时可见的记忆集**」，**不是**「事实的生效区间」。本仓源码 `validTime` / `recordedTime` / `valid_from` / `recorded_at` **0 命中**（已核实）。⇒ 引入它等于**新增一类字段体系**，属**能力扩张**，须单独 ADR 论证，**不随重点材料一起做**。 |
| **它自报的评测分数**（LongMemEval / MemDaily / PerLTQA） | 与 ADR-0060 同一纪律：**别家的语料与后端，不能当本系统的证据**。**未复现**，不得引用为「已验证」。 |
| **`namespace` 多租户** | 本仓无此职责；它自己也明写 `namespace` **不是**认证 / 授权 / 加密 / 侧信道边界。 |
| **它的代码** | 许可虽是 Apache-2.0（**理论上可复用**，与 OpenViking 的 AGPLv3 不同），但本仓既定口径是「**只借鉴思想与文档结构，不引依赖**」。**本条目不改变该口径。** |

### 5. 许可边界（与 OpenViking 的关键差别）

- **HL-Mem = Apache-2.0**；本仓 = MIT；**OpenViking 主工程 = AGPLv3**。
- 差别是实质的：OpenViking 那条是「**不可抄代码**」的硬约束（ADR-0065 据此只写形状对照）；
  HL-Mem 在许可上**允许**复用。
- **但结论相同**：本仓**仍不引其代码或依赖** —— 理由是**架构判据**（ADR-0001 否决常驻服务；
  ADR-0043 / 0060 否决向量库），**不是许可**。
- **把「许可允许」误读成「该引」，是本次最需要防的滑坡。** 许可放宽的是**复制权**，
  不是**架构适配性**；两者的判据不可互相替代。

## Alternatives Considered

| 备选 | 否决理由 |
|---|---|
| 只登记 `references.md`，不立 ADR | 用户先定「重点材料」，随后确认要 ADR。且对标结论里有**四条「不吸收 + 理由」**（LLM 提取 / 常驻服务 / 物理删除 / 双时间），这些是**决策**，须可回溯；只写在 `references.md` 会与「登记备查」的性质混淆 |
| 照 ADR-0065 那样写成「**吸收**」 | **不成立**：0065 的对象是用户已决定吸收的；本对象是「重点材料」。**把「重点看」写成「已吸收」= 冒充结论**（本仓纪律：不把缺件说成已完成） |
| 立 ADR 并**立刻**实现能力矩阵 | 用户本轮授权范围是「立 ADR + 记 BACKLOG + 补 CHANGELOG」；实现是独立工作量，**升为 D8** |
| 采信第三方对 HL-Mem 的转述 | 与 ADR-0065 同纪律：**一律以仓库内 `LICENSE` / README / raw 文档为准**。本轮全部读数均取自一手 raw 文件 |
| 因它「更小、更工程化」而抬高证据强度 | **反向纠正**：7 ⭐ / 单人维护 / 983 提交 ⇒ 措辞按此收紧，**只说「值得看」，不说「被验证」** |

## Consequences

### 正
- 在**术语层**把「重点材料」与「已吸收」分开（除 D8 外不动代码），避免语义滑移。
- 记下**一条硬冲突**（LLM 提取 vs 纯函数派生），使后续对标不会误把它的写入路径当范本。
- 精确化了一处本仓缺口：README「默认开关」表**缺三列**，且「降级行为」列的缺失**正对 ADR-0049**。
- 许可判断与 OpenViking **明确区分**（Apache-2.0 vs AGPLv3），同时**不让许可放宽架构判据**。
- 顺带纠正了本轮我自己在上一条文档改动里的**过度表述**（见 §2 末注）——这正是「先核实再落笔」的价值。

### 负 / 已知边界
- **本 ADR 没有任何代码 / 配置 / 行为改动**（与 ADR-0065 同型）。
- 对标表「本仓现状」一列是**源码实读**（`core/forget.ts` 头注释、`validTime` 等的零命中检索、
  `README.md:113-130` 的表结构与列数），但**未在运行进程验证**行为差异。
- HL-Mem 的评测分数、其 MCP 与本机 DSH `0.1.5-rc.2` 的兼容性、`sqlite-vec` 路径 —— **均未在本机实测**。
- 「双时间」「物理删除」两条的**不吸收理由是架构判据**（ADR-0031 / 新增字段体系的成本），
  **不是说它们不好**；若将来出现真实诉求（跨时间取证 / 合规删除），应**另立 ADR** 重新论证。
- 它的 `docs/capability-matrix.md` 我只读了前段（约 7 KB），**其余特性行未逐条读完**。
