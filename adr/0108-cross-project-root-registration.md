# ADR-0108: 跨项目根注册（可信根）—— 把「别的根」从不可判定变成可判定

- 状态：**草案**（设计已定，**未实现**；实现前不得引用本条件为「已落地」）
- 决定日期：2026-09-25
- 关联：**ADR-0059**（引用漂移检测 —— 本条是它「负/已知边界」里那条待决项的落地设计）·
  **ADR-0049**（缺件不静默 —— 「未判定」必须可见，**不得**说成已验证）·
  **ADR-0087**（**不允许建没有消费方的机制** —— 本条先点名消费方才动）·
  **ADR-0086**（受保护契约面登记册 —— 新配置面是否入册见 §5）· **ADR-0062**（接线审计）
- 定位：回答「**哪些外部的根可以被信任来解析本仓引用，凭什么、谁能加、加了以后判据怎么变**」。

## 1. Context

- **`ADR-0059` 的实测**：全库 2530 次路径状引用中 **243 次（9.6%）不可解析**，主体是**跨项目相对路径**
  （如 `scripts\wslc-utils.ps1` 来自 `wslc1` 仓库）——相对本工作区根**确实不存在**。
- **本会话的归档层实测**（`node tools/citation-audit.ts . --include-archive`）：归档层引用 **582** 处中
  **未判定 270** 处 = **192 处**「带目录的路径在本仓 / 材料里都找不到」+ **78 处**「同名 N 个不猜」（N 高达 **155**）。
- **已被证伪的做法（不得复活）**：`ADR-0059` 明写**不猜** —— 「按名字猜」被实测证伪**两次**
  （`ADR-0058` 的 9 例包 ID 假阳性；第 3 轮按后缀猜路径同样错：`xh` → Firefox）。
- **用户决策（2026-09-25）**：**做**「跨项目根注册 + 可信度设计」。本条把它落成可实现的形态。

## 2. 决定

**新增一处「可信根注册表」，只做一件事：让本仓引用能在「已注册的别的根」上被解析并**比行数**。**
它**不改变**判据的强度 —— 仍然**只答「越界了没有」**，不判内容对不对。

### §2.1 配置面（放哪、长什么样）

- **落点**：`tools/trusted-roots.json` —— 与 `tools/{audit-ratchet.baseline,retrieval-eval.baseline,
  retrieval-eval.protocol,toolset-authority,toolset-seed}.json` **同类**（本仓既有形状：**工具的离线数据放 `tools/*.json`**）。
  **不进 `package.json` 的 `files`**（它不是产品面），**进版本控制**（可审计、可回滚）。
- **条目形状**（每条都要能回答「谁、何时、为什么」）：

  | 字段 | 含义 | 约束 |
  |---|---|---|
  | `root` | 根的**绝对路径**或**相对本仓**的路径（如 `../wslc1`） | 相对写法优先（换机更耐用） |
  | `label` | 人读名字（如 `wslc1`） | 必填，用于报告里点名 |
  | `addedBy` | `human` / `agent` | ⚠ **只接受 `human`**（见 §2.3） |
  | `addedAt` | 日期 | 必填 |
  | `reason` | 为什么信这个根（一句话） | 必填；空 ⇒ 校验失败 |
  | `scope` | 允许解析的**前缀**（如 `scripts/`） | 可选；缺省 = 整个根。**收窄优先** |

### §2.2 解析顺序与判定语义（**判据只有一份实现，继续共用 `judge`**）

1. 本仓相对（现状）
2. **已注册根**（按注册表顺序；**唯一命中才算**，多根同时命中 ⇒ **仍不判**）
3. `_src` 材料根（现状）
4. 裸文件名兜底（**唯一**命中才算，现状）
5. 以上都不成 ⇒ **未判定**（不判、不报红 —— `ADR-0049`：缺件必须可见，但**不得**把缺件说成已证或已证伪）

**根不可用（不存在 / 读不动 / 无权限）⇒ 该条回落为「未判定」**，并在报告里**点名是哪个根不可用**
（不许静默降级成「找不到该文件」，那会把「根丢了」伪装成「引用错了」）。

判定内容**仍然只比行数**：不读语义、不判内容位移、**不联网**。

### §2.3 授权模型（**inv 178 边界**：谁能加根）

- **只有人能加根**。`addedBy` 只接受 `human`；**agent 不得自行写入**本文件。
  **理由（本条的硬核）**：agent 若能自行加根，就等于**可以自己把「未判定」变成「已判定」** ——
  判据的**证据面被被判者自己控制**，那就是自己给自己发合格证。这与本仓「不猜」「不臆造机制」一脉相承。
- **人工加根的动作 = 一次可审计的提交**（进版本控制、可回滚、可 review）。
- **加/删根之后，棘轮基线必须【有意】更新**（同 `v1.21.14` 的教训：不许让基线静默漂移）。

### §2.4 消费方（`ADR-0087` 要求：**先点名消费方才动**）

| 消费方 | 怎么用 |
|---|---|
| `tools/citation-audit.ts . --include-archive` | 归档层度量：未判定数应**下降** |
| 门 ⑥（`audit:docs` 的当前态引用检查） | 当前态文档：同上 |

**没有第三个消费方。** ⇒ 不建 UI、不建自动加根、不建跨仓同步。

### §2.5 与受保护契约面（`ADR-0086`）的关系

`tools/trusted-roots.json` 是**新配置面** ⇒ 按 `ADR-0086` 的做法，它应作为**一条受保护契约**登记
（`allowed` = 字段集合 · `forbidden` = 语义（见下 · `stability` = 兼容策略）。
**`forbidden`（写死，防止后来者误用）**：
- **不得**把「已注册根」当作**内容正确**的依据（它只支持「解析 + 比行数」）；
- **不得**在根上做**语义**判定（内容是否搬走了）；
- **不得**让 `scope` 为空字符串以外的通配（`*`）—— 通配等于没注册。

## 3. 备选与代价（已考虑并拒绝）

| 备选 | 为什么不选 |
|---|---|
| 按名 / 按后缀**猜**工作区基线 | **已被实测证伪两次**（`ADR-0058` 9 例假阳性；`xh`→Firefox）——`ADR-0059` 已明确排除 |
| 固定约定目录（如一律 `../*`） | 把「哪些根」**隐式化**：换机后行为随目录布局变，且无法回答「凭什么信它」 |
| **agent 自动加根** | 授权失控（§2.3）：被判者自己控制证据面 |
| 只扩 `_src`（材料根） | `_src` 是**材料台账**语义（外部资料），不是「跨项目源码根」；混用会污染 `MATERIALS.md` 的口径 |
| 维持现状（接受 270 处未判定） | 这是 `D2` 原状；用户 2026-09-25 决定不做这一项 |

## 4. 后果

- **正向**：192 处「带目录找不到」里，凡能**唯一**命中已注册根的，从「未判定」变成「可判定（比行数）」；
  **未判定数下降**是唯一可量的成功信号。
- **负向 / 风险（如实列出）**：
  1. **假阳性风险回来了**：一旦注册了错根（或 `scope` 过宽），会把**别的文件**当成目标 ⇒ 制造**假越界**。
     缓解：`scope` 收窄优先；**新增越界逐条人工复核**（不许只看计数）。
  2. **可移植性**：绝对路径换机即失效。缓解：优先相对写法 + 「根不可用 ⇒ 未判定 + 点名」。
  3. **多一处配置面 = 多一处漂移源**。缓解：进版本控制 + 棘轮 + 契约登记。
- **不变**：判据强度（只答越界）、`ADR-0059` 的「不猜」、`ADR-0049` 的「缺件不静默」。

## 5. 完成判据（实现后才能置「已接受 · 随 vX.Y.Z 落地」）

1. `tools/trusted-roots.json` + 校验（字段齐、`addedBy === "human"`、空 `reason` 拒收）；**坏件不得静默**（`ADR-0049`）。
2. `judge` 的解析顺序加**唯一命中**的一档；**判据仍只有一份实现**（`v1.21.7` 已抽出的那个 `judge`）。
3. **标定**（本仓纪律：新能力必须配正/负/控制变量）：① 正对照：单根唯一命中 ⇒ 可判定；② 负对照：**多根同名 ⇒ 仍不判**；
   ③ 控制变量：根不可用 ⇒ **未判定 + 点名根**（不得变成「找不到」）；④ 控制变量：`scope` 外 ⇒ 不参与解析。
4. **实测**：归档层「未判定」数**下降**，且新增越界**逐条复核**过（是真越界）。
5. `ADR-0086` 登记册加上这一条契约；棘轮基线**有意**更新。

## 6. 未核 / 已知边界（**不缩小承诺**）

- **未核**：192 处里**究竟有多少**能靠注册根真判出来 —— 需要先列出本机「本仓之外、被本仓引用过的根」清单（尚无）。
- **未核**：inv 178 的**具体条款文本**（本节按「谁能改权威语义」的口径写，未逐字比对 178）。
- **未定**：注册表**是否**需要在报告里**暴露绝对路径**（涉及本机信息外泄面）；`ADR-0059` 只约束「不猜」，未约束披露。
- **不做**：不猜、不联网、不自动加根、不用 LLM、不把「已注册」当内容正确。
