# ADR-0090: 实装 rtk 的三条判据形态（BACKLOG D9 / D10 / D11 —— 甲-1 / 甲-2 / 甲-3）

- 状态：**已接受**（2026-09-15 / `v1.15.89`）
- 关联 ADR：**ADR-0087**（判定来源：`rtk` 的 8 条形态，本轮实装其中 3 条）· **ADR-0049**（缺件不静默）·
  **ADR-0072**（标签不得强于事实 —— D11 是它的续）· **ADR-0001**（不引重服务 —— 恢复载体不许用 SQLite/gzip）·
  **ADR-0085** §8.7（能推出来的字段不要手写）· **ADR-0003 / 0075**（派生件不是 source）
- 关联待办：`BACKLOG.md` 的 **D9 / D10 / D11**（三条同代，本轮一并结案）

`adr/0087` §C 当初明确**不实装**，理由是「每一条都有一个必须先拍板的前置」（这是决定，不是漏做）：

| 条目 | 前置是什么 | 当初为什么停 |
|---|---|---|
| **D9**（甲-1） | ① 恢复载体用什么（**不许** SQLite/gzip，ADR-0001）② 存储不可用时是否允许有损 | 未被授权替用户选 |
| **D10**（甲-2） | 中文 token 口径（rtk 用**字节**/4，中文每字 3 字节 ⇒ 会把方向判反） | 口径未定 |
| **D11**（甲-3） | 落地形态会动**已签入的离线棘轮** `tools/toolset-authority.json` 与双向棘轮测试 | 改动面未定 |

用户对本轮答复是「**都要**」（即：D 类九份真读 + 这三条实装，两件都做）⇒ **前置由本条拍板并写下来**。

## Decision

### A. 三个前置的口径（**先定，再动手**；这是本 ADR 最要紧的一节）

**① D9 的恢复载体 = 工作区里**已有的源文件**，不新增任何存储。**
rtk 必须造一份存储（SQLite + gzip + 内容哈希去重 + 老化），因为**它压的是命令输出、原文本来不落盘**；
**本仓相反**：被省略的内容本来就写在 `.shadow/<日期>/<入口>.md` 与 `.shadow/_index.md` 里
⇒ **恢复句柄 = 源文件路径（+ 段名/入口名）**，取回 = 读那个文件。**零新增存储、零新依赖**
（ADR-0001 因此不需要被破例），也就**不需要**自定义「同 hash 主键去重」与「老化」语义
—— 那是 rtk 被迫发明的，本仓没有对应问题。⇒ 前置①的答案是「**载体 = 权威源本身**」。

**② 「拿不到句柄时不许输出有损结果」的本仓口径（必须写清楚，否则会被误读成「永不截断」）。**
甲-1 的原话是 *"Never emit an unrecoverable truncation marker: fall back to full raw"*，
它在 rtk 里成立的前提是「退回原文**是免费的**」（原文本来就已产出，压缩只是优化）。
**本仓相反**：`.shadow/_index.md` 实测 **2199 KB / 24639 行** ⇒ 对**索引路径**退回原文
等于**放弃预算**（那正是 `v1.15.85` 修掉的缺陷）。故本仓拆成两条：

- **有损输出必须显式声明「可复取」或「不可复取」，二者必居其一**，**不许**静默省略；
- **拿不到句柄 ⇒ 不许降档**这条**逐条**适用（召回路径：降档是有损的，没有句柄就不降，保持原档 = 退原文）；
  **索引路径**（单文件可达 MB 级）**不适用「退原文」**，改用「**省略 + 显式写『不可复取』+ 原因**」。
  ⇒ 这条差异不是打折扣：把「不可复取」**写出来**才是甲-1 的实质（它防的是**看起来可复取**的损失标记）。

**③ D10 的单位 = 字符数**（与预算 `max_tokens × 4` **同单位**），不用 rtk 的「字节 / 4」。
理由（`BACKLOG` D10 已记方向）：ASCII 1 字节/字、中文 3 字节/字 ⇒ 比**字节**在**中英混排**下会把方向判反。
本条把这条口径**做成了对照断言**（见 §C ② 的实测用例），而不是只写在文档里。

**④ D11 的落地 = 新增类型化字段作唯一事实源，`note` 由它派生（渲染逐字不变）。**
取值域是**类型** `VerSrcKind = "measured" | "authority" | "none"`（`core/util.ts`）；
`core/toolset.ts` 的 `tool()` 不再收字符串，`note` 用 `verSrcLabel(verSrc)` 渲染；
下游 `claimOf()` **不再正则反解散文**，改读 `verSrcKind` / `verSrcVersion`；
未知/非法取值一律返回 `null`（=「未标」），**不许默认成强档**。

### B. 实装（文件级）

| 面 | 位置 | 动作 |
|---|---|---|
| 损失形态 / 句柄 / never_worse | **新** `retrieval/loss.ts` | `Lossiness{ none, tail, whole }` · `RecoverHandle{file, locator}` · `handleText` · `neverWorseChars`（单位 `chars`）· `lossLine`（可复取/不可复取二选一）· `excerptWorthwhile`（区分「本来就短」）· `tierLossNote` |
| 索引路径 | `retrieval/render.ts` | `renderIndexBudgeted(idx, maxChars, source = INDEX_HANDLE)`：加**损失行**（形态 + 句柄/不可复取）；出口改为 `neverWorseChars(body + notes, raw)`；披露里的段名**限长**（见 §自检 ②） |
| 召回路径 | `query/query.ts` | 降档前取句柄：**无句柄不降档**；降档必须**真省字**（`degraded.length <= render.length`）；「本是够长却没给片段」记进披露，输出 `tierLossNote`（**条内**损失）与信封（**条级**损失）分开 |
| 出处类型化 | `core/util.ts` / `core/toolset.ts` | 新增 `VerSrcKind` + `verSrcLabel`（查表）；`Capability` 增 `verSrcKind` / `verSrcVersion`；57 个调用点 `"权威核验"` ⇒ `"authority"`；两个 provider 条目显式 `"none"` |
| 出处读取 | `tools/toolset-authority.lib.ts` / `.ts` | `claimOf(cap)` 读类型化字段；`ledgerMismatch` 入参同步 |

### C. 判据与测试（**每条都配反向不变量**）

**① 甲-1/甲-2 的纯函数面**：**新** `test/loss-and-handle.test.ts`
—— 形态×句柄**互斥可判定**（有句柄不得说不可复取，反之亦然）；`loss: "none"` ⇒ **零输出**；
`neverWorseChars` 的空输入边界与「相等 ⇒ 保留」；**索引路径**必须给句柄、`source: null` 必须写「不可复取」、
披露比原文长时**逐字退回原文**。

**② D10 的口径对照（实测，不是推断）**：同一条「变长了」的输出，按**字符**判得出、按**字节**判不出 ——
`raw = "中"×60`（60 字符 / 180 字节）vs `longer = "a"×62`（62 字符 / 62 字节）：
`neverWorseChars(longer, raw) === raw`（判出更长），而 `byteLength(longer) < byteLength(raw)`
（字节口径会漏判）。断言两条都写在测试里 ⇒ **口径被锁住，不是注释**。

**③ 甲-2 在既有用例上的一次行为变更（诚实记录）**：`test/recall-envelope.test.ts` 的
「连第一节都放不下 ⇒ 硬截断必须自报」原先用**单行 400 字**的语料，加守卫后**必然**退化：
原文 403 字而披露要 400+ 字 ⇒ 守卫退回原文（**那才是没有损失的一份**）⇒ 该断言**必然**失败。
处理：**把语料放大到 4003 字**（该用例原意不变：超大原文 + 极小预算 ⇒ 硬截断且自报），
并**新增**一条断言把「披露比原文长 ⇒ 退回原文」钉住。⇒ 这不是「改期望值掩盖失败」：
两件事各自有断言，且新行为是 D10 的**规格**。

**④ D11 的反向不变量**（`test/toolset-authority.test.ts` 新增 ⑧）：**渲染与字段不许分叉**
（101 条逐条比对：`claimOf(c)` 的值必须等于 `note` 散文里那一段，**用测试自带的正则做独立 oracle**）·
**弱档不得被散文升格**（字段 `authority` + 散文写「实测」⇒ 判据取弱档）·
字段缺失/非法 ⇒ 未标（不得默认强档）· **把弱档合并进强档必须被检出**（合成行：`权威核验`→`实测` 且本机读数不符）。

**⑤ 门槛**：`npm run verify` ⇒ **60/60 ALL PASS**（新增 `test/loss-and-handle.test.ts` 一个检查）。
`audit:ratchet` 保持**通过**（见 §自检 ①）。

## Alternatives Considered

| 备选 | 否决理由 |
|---|---|
| 照 rtk 造一份「省略内容」的**存储**（SQLite/gzip + 哈希去重 + 老化） | 违反 ADR-0001；且**本仓没有它要解决的问题** —— 原文本来就在盘上，句柄即路径 |
| 索引路径也照字面「拿不到句柄就退原文」 | 会把 `.shadow/_index.md`（实测 2199 KB）整篇塞回 agent 上下文 = **撤销 v1.15.85 的修复**；改用「显式声明不可复取」保住预算与诚实 |
| 逐条在记忆行尾追加省略标记（而不是一次信封） | 输出成本 O(条数) 而非 O(1)；本仓既有口径是**信封一次披露**（`truncationNote` 同族） |
| D10 沿用 rtk 的「字节 / 4」 | 中英混排会把方向判反（§C② 已做成断言）；且本仓预算本来就是**字符**口径，换算只会引入误差 |
| D11 只把 `verSrc` 类型化、保留 `note` 正则反解 | 那就是「类型化字段 + 第二个事实源」；ADR-0072 的教训正是**弱档折进散文** |
| 直接改 `tools/toolset-authority.json` 让棘轮过 | 清单是**签入的离线证据**（记录核验当日台账声称什么）；渲染逐字不变正是为了**不动它** —— 本轮实测确实一行未动 |

## Consequences

### 正

- 「**被省略**」与「**本来就短**」在输出上**可区分**了（这是 D9 的完成判据①），且被省略的部分**有句柄可复取**。
- 有损路径多了一道**全函数守卫**（出口唯一）：*压完没变短 ⇒ 别压*。
- `verSrc` 从「散文里的一段字符串」变成**类型化字段**：弱档**折不进**散文，缺失**不会**默认成强档。
- **零新增依赖、零新增存储、零改签入清单**（63 行 `core/toolset.ts` 的 57 处只是把字面量换成类型取值）。

### 负 / 已知边界（诚实）

- **召回路径的披露有固定成本**：只要本次返回里存在「本该有片段却被省略」的条目（真语料里 L0 档占比很高），
  输出就多两行（约 150–250 字）。**未做**开关；若将来嫌贵，取舍应显式写进 README 的默认开关表（不是悄悄去掉披露）。
- **句柄的可用性依赖路径**：本仓句柄是**路径字符串**，不是句柄对象 —— 文件在省略之后被删/移，
  取回会失败。**未做**「取回时校验存在性」（那需要一个读取入口；`read_shadow` 无此模式）。
- **`neverWorseChars` 只比长度**：它不判断「压缩后是否语义等价」（本仓不做语义压缩，故不构成缺口，但边界要写下来）。
- **索引路径与召回路径的口径**不同（前者「不可复取」可接受、后者不许降档）—— 差异已写进 §A②，**不是遗漏**。
- **`test/recall-envelope.test.ts` 的既有用例被放大语料**（§C③）—— 这是行为变更，已在此留档而不是只改代码。

## 自检（本轮踩到并修掉的坑）

1. **`audit:ratchet` 一度变红（B 键 97 → 100，+3）**：新写的三个**字符串判等**（`kind === "measured"` /
   `kind === "authority"` / `loss === "none"`）被接线审计读成「只读不写的判断值」。
   **没有去改基线**（那会让门更松）：改成**查表**（`VER_SRC_LABEL[...]` / `LOSS_WORD[...]`）后回到 97 ——
   顺带把「枚举 → 标签」的映射收成**唯一一份**。
2. **披露会被段名撑爆（实测）**：`renderIndexBudgeted("## " + 4000 字, 20)` 的「未返回的段」把**整行**当段名抄了一遍
   ⇒ 披露自己 4000+ 字 ⇒ 守卫只能退回原文（假象：以为「硬截断没自报」）。**修**：披露里段名**限长 48 字**
   （超出写「段名共 N 字」）—— 披露只留**名字**，不复制内容。
3. **`claimOf` 的调用点不止一处**：`ledgerMismatch` 内部也调它 ⇒ 改签名必须同时改 `tools/toolset-authority.ts` 的
   入参类型；否则「离线棘轮走新判据、CLI 走旧形状」——正是**同一个判据两份实现**的老坑（`AGENTS.md` 已立规矩）。
4. **`references-agents` 的上跳级数**（同日另一条工作时踩到，与本条无关但同源）：
   与仓库根不同级的路径**不能凭印象写**。本条的「怎么重放」逐条实跑过。
