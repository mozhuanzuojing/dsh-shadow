# ADR-0094: README 不再保留版本历史表；`audit:docs` ④ 的锚点从「表里那一行」挪到「当前版本行」

- 状态：**已接受**（2026-09-15 / `v1.15.92`）
- 关联 ADR：**ADR-0085** §8.7/§8.8（「能推出来的字段不要手写」+ `audit:docs` 的产生）·
  **ADR-0072**（标签不得强于事实 —— 本例是它的同族：门的锚点不得指向一个会消失的制品）·
  `AGENTS.md` 的文档归属表（**同一条事实只写一处**：`CHANGELOG` 拥有历史层）

## Context

用户 2026-09-15 连问三轮（「能力/中心思想是什么」「看不懂」「插件好庞大」）后下「**README 重新设计**」，
先明确「**版本历史表不要动**」，随后又改成「**删除版本表**」。

同一个动作会同时动到两样东西，必须分清：

- **制品**：README 里那张 116 行的版本历史表（每版一行压缩摘要 + 指向）；
- **判据**：`audit:docs` **检查 ④** —— 「README 的当前版本行不得复制 `CHANGELOG` 条目」，
  它当时**锚在**那张表的当前版本行上（`tools/docs-consistency.ts` 的 `readme.findIndex(l => l.startsWith(``| v${ver} |``))`）。

## Decision

1. **删制品**：README 去掉整张版本历史表（**757 → 634 行**）。历史层由 `CHANGELOG` **唯一拥有**
   （`AGENTS.md` 的归属表：`CHANGELOG.md` owns「每个版本的历史归档」；README owns「当前状态」）。
2. **挪锚点、不改判据**：检查 ④ 改为盯 **README 的当前版本行**（行首 `**当前版本：`）——
   那是**每次发版都会更新**的行，不会随制品一起消失。判据本身（≥40 字连续逐字重复、阈值 40、
   只查当前、不碰历史）**一字未改**；退出码语义不变（0 一致 / 1 重复 / 2 结构缺失）。
3. **标定同步，并如实标注重叠**：`tools/docs-consistency.selftest.ts` 的 fixture 从「造一行表行」改为「造当前版本行」；
   ⑰ 从「表里缺当前版本那一行 ⇒ 2」改为「README 缺当前版本行 ⇒ 2」，并在注释里写明
   **该分支通常已被检查① 覆盖**（① 也要求这一行存在）—— 保留它作**兜底**，不假装它仍在独立干活。
   报文里的复发计数同步为 **5 次**。

## Alternatives Considered

| 备选 | 否决理由 |
|---|---|
| 保留「只含当前版本一行」的小表 | 那是**留着制品、假装删过**：一行表仍在回答「历史表长什么样」，而它的唯一消费者（检查④）已不再需要它 |
| 删表并**顺手删掉检查 ④** | 把「改制品」变成「减判据」：④ 挡的是**真缺陷**（v1.15.66 §5 / v1.15.72 / v1.15.74 / v1.15.90 已复发 4 次） |
| 保留表、只删表里的**历史行**、其余不动 | 用户要的是**删表**；且「只留当前版本一行」与上一条同病 |
| 让 ④ 同时查「当前版本行 + 若存在表则也查表」 | 判据会**依制品存在与否而变**（同一份 README 两种行为）—— 与「判据只有一处、行为可推理」相冲突 |

## Consequences

### 正

- README 回到「**当前状态 + 面向使用者的表**」这一个归属（`AGENTS.md` 早就这么定），历史只有一处。
- 检查 ④ 的锚点从「会被删掉的制品」换成「发版必然更新的行」——**门的寿命不再绑定制品**。
- 标定里那句「该分支已被 ① 覆盖」是**新的信息**：此前没人注意到两条门在这一点上重叠。

### 负 / 已知边界（诚实）

- **README 失去「最近几版在干什么」的一眼概览**（那张表是压缩摘要层）；要看历史必须去 `CHANGELOG`。
  这是用户明确选择的取舍，不是遗漏。
- 检查 ④ 的**结构缺失分支**在实践中被检查 ① 遮蔽（① 先跑且要求同一行存在）⇒ 它只在「① 通过而该行又消失」这类
  不可能态下生效；**已如实写进标定注释**，没有把它算成独立覆盖。
- **README 正文里仍有多处维护者面**（受保护契约面 / 模块归属表 / 工具集台账）本轮只**下移**、未重写 —— 记为下一步。
