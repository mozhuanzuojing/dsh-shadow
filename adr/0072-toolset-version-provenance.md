# ADR-0072: 台账的「实测」标签比事实强 —— 改正默认值，并把权威对照签入成可离线棘轮的清单

- 状态：**已接受（2026-09-11）**
- 决定日期：2026-09-11
- 关联 ADR：**ADR-0055**（台账两级）、**ADR-0058**（台账扩源；`verSrc` 正是它引入的诚实机制）、ADR-0049（缺件不静默）、**ADR-0070**（漂移审计工具 —— 本轮线索源自它的检测 B）、ADR-0071
- 关联待办：`../BACKLOG.md` 的 **T5**（本 ADR 复核掉一条 B 键：`c.kind=provider`/`c.kind=reference`）、**V2**（probe 旗标未逐项真跑 —— 本 ADR 实测了它的后果）
- 版本：`1.15.29`

## Context

`tools/audit-drift.ts` 的检测 B 报出 `c.kind=provider` / `c.kind=reference` 两个键跨
`core/toolset.ts` 与 `core/toolset-exec.ts`。**先判它是不是漂移**：

- `toolset.ts` **声明** `kind`（`Capability.kind: ToolKind`，**类型必填**），
  `toolset-exec.ts` **消费**它（探测超时、渲染、审批）。
- ⇒ **正当的分层**（生产者/消费者），不是漂移。顺带核对了它文档化的边界不变量：
  `core/toolset.ts:3` 写「两级台账**必须分清，否则边界就糊了**」，且 `degradesTo` 注释规定
  「reference 填『不影响插件行为』」。**实测 107 项全部满足**（105 reference 均含该口径、
  2 provider 均给确定性退路 + `provides` + `install`）—— 边界没糊，但**这条不变量没有棘轮**。

于是顺着「台账诚实性」这条线查下一层，命中了**真问题**。

### 事实链（全部实测）

**① 标签与事实不符。** `core/toolset.ts` 对 `verSrc` 的定义：

| 标签 | 定义（原文） |
|---|---|
| `"实测"` | 在**本机**跑该条目的 probe（如 `--version`）拿到版本号 |
| `"权威核验"` | 取自 `winget show` 权威目录 —— **最新发布版**，不代表本机已装 |

而 v1.15.10 加入的 **44 条全部标着 `"实测"`**（该参数原默认值），数字却来自 winget 目录：

| 证据 | 读数 |
|---|---|
| 44 条标签「实测」中，与 winget 权威版本**逐字一致** | **35 条**（手工取本机版本不可能如此吻合） |
| `fzf`：台账「实测 **0.74.3**」 | 本机 `fzf --version` = **0.73.1**；且来自 **scoop**（`C:\Users\l\scoop\shims\fzf.exe`），**winget 里没装 fzf** |
| `zoxide`：台账「实测 **0.10.0**」 | `winget list` = **已装 0.9.9 / 可用 0.10.0** ⇒ 台账抄的是**「可用」列**（最新发布版） |
| 本机可检出的 8 条「实测」条目里，台账版本**比本机新**的 | **7 条**（`gh` 2.100.0→2.93.0、`uv` 0.12.12→0.11.17、`mise` 2026.8.5→2026.5.4、`just` 1.58.0→1.56.0、`7zip` 26.03→26.01 …），**方向一致** ⇒ 不是巧合 |
| 唯一相符的 | `ffmpeg` 9.0.1（本机确为 9.0.1） |

⇒ **「实测」这个标签比事实强** —— 正是 v1.15.14 造 `verSrc` 要防的那种谎。

**② 版本误标**不可能被发现**，因为核验器从不用版本判定**：
`tools/winget-verify.ts` 的 `verifyLedger` 传 `expectedVersion: null`（注释写「版本不参与失败判定，只报告」），
于是同文件 `:81` 的 `verDrift` 分支**从未生效**。实跑 `npm run verify:toolset`：
**「核验 101 项：✅ 一致 101 · ⚠ 版本漂移 0」** —— 那个 `0` 是**因为版本没参与判定**，不是因为没有漂移。
（把台账版本当真期望值去核验：**13 条老化**。）这是同一族缺陷的**第八个实例**：
机制存在（`verDrift` + `expectedVersion` 参数），**没接到调用点**。

## Decision

### 1. 改正默认值：`verSrc` 默认 `"实测"` → `"权威核验"`

那 44 条**确实不是实测**（证据见上），故把**默认**改为与事实一致的标签。
标签本身保留两个值（`"实测"` 仍可用于**真在本机跑过 probe** 的条目），
并在参数文档里把这次的实测证据写进去 —— 避免以后有人「顺手改回默认实测」。

### 2. 新增 `tools/toolset-authority.ts`：把权威对照**签入**成清单

- 逐条真调 `winget show`，**把台账登记的版本当真期望值**（补上 §② 的缺口）；
- 同时**探测本机**，把 `machineVersion` 记进清单 —— 它是「`"实测"` 标签是否成立」的唯一判据；
- 产出 `tools/toolset-authority.json`（**随包签入**）：每条记录
  `ledgerVerSrc` / `ledgerVersion` / `authorityVersion` / `machineVersion` / `status`。
- 用法：`npm run verify:authority`（刷新）/ `npm run verify:authority:check`（只读比对）。

### 3. 新增离线棘轮 `test/toolset-authority.test.ts`（5 组断言）

| # | 断言 | 作用 |
|---|---|---|
| ① | 清单 `counts` 与 `rows` 实际相符 | 清单不得自相矛盾 |
| ② | 台账的（出处 + 版本）与清单**逐条一致** | **改了台账就必须重跑生成器**（否则红） |
| ③ | **没有任何「实测」条目缺本机读数佐证** | 本 ADR 的**核心不变量** |
| ④ | **正对照**：4 条合成记录（相符的实测 / 不符的实测 / 无读数的实测 / 权威核验本机不同）⇒ 恰好报 2 条 | **证明检测器真会报警**（否则③的「0 条」可能只是检测器不工作） |
| ⑤ | 有 winget 包的条目**全部**能解析出（出处 + 版本） | 口令不可解析则棘轮形同虚设 |

**关于 ③ 的诚实说明**：它当前平凡成立（台账 0 条标「实测」，是**因为 §1 改了默认值**）。
**④ 正对照就是为这一点存在的** —— 没有它，③ 的绿说明不了任何事。
**这是本仓 ADR-0062 §2「先证工具，再用工具」的又一次应用。**

### 4. 测试还纠正了我自己的一处判据范围错

首跑 ② 报 **6 条假不一致**（`zg`/`semble`/`tmux`/`viddy`/`tig`/`ip`「清单无此条」）——
原因：清单按「**有 winget 包**」的范围生成（101/107），我却拿**全部 107 条**去比。
修正为**只比对 `winget` 非空的条目**，并把这条范围写进函数注释。
（这 6 条中 4 条正是「无可靠安装方式、宁缺勿编」的条目。）

## Alternatives Considered

| 备选 | 否决理由 |
|---|---|
| 把那 44 条的版本**改写成本机实际版本** | 那会把台账从「目录参考」变成「本机快照」，**性质变了**：台账的用途是「这个工具在 winget 上是什么包/什么版本」，本机装没装是另一回事。且本机没装的条目无从取材。**改标签（不改数）才是对齐事实** |
| 直接把 `verSrc` 参数删掉（既然全是权威核验） | 它区分的是**两种语义**，将来真做本机实测时还要用。且删除会丢掉「这次为什么改默认值」的可追溯点 |
| 把清单里的 `machineVersion` 也放进断言、测试时重探测 | **会把机器状态写进断言** —— 本仓 `toolset-catalog` ④ 曾因机器相关断言**恒红**（v1.15.13 修过）。故清单只作**留档**，测试离线比对 |
| 让棘轮断言「老化 = 0」 | 老化是**目录在推进**的正常现象（13 条），断言 0 会让测试随上游发布而常红。**只让老化可见，不判它错** |
| 顺带把 `verify:toolset` 直接改成传 `expectedVersion` | 那会改变那条命令的**退出码语义**（原本「版本漂移」不算失败）。本 ADR 用**新命令**表达更强的核验，不动既有命令的契约 |
| 顺手把台账版本更新到 winget 现值 | 无意义：改完下次还会老化。且会掩盖「老化可见」这一用途 |

## Consequences

### 正
- **标签与事实对齐**：`verSrc` 默认改为权威核验后，101 条**全部**标注准确、**可复核**
  （重跑 `npm run verify:authority` 即得）。
- **版本误标首次可见**：清单把「台账声称 / winget 权威 / 本机读数」三者并列留档，
  13 条老化与 9 条本机差异（如 fzf 0.74.3 vs 0.73.1）都不再隐性。
- **两处结构性问题被修**：① 默认值导致的系统性误标；② `verDrift` 从未生效的接线缺口
  （新命令真的用它）。
- **离线棘轮**：台账被静默改版本/改出处而没重跑生成器 ⇒ 测试红。不联网也能守。
- **工具经正对照标定**（④），不是「报 0 就信 0」。
- 补上了 `core/toolset.ts:3`「两级边界」不变量的实测（107 项全满足）—— 并记入 T5 复核结论。

### 负 / 已知边界
- **清单里的 `machineVersion` 是生成时那台机器的读数**，属**证据留档**；测试不重探测
  ⇒ 它不会自动发现「换了机器」。这是**有意的**（避免机器相关断言）。
- **「老化」不判错**：13 条台账版本落后于 winget 现值，会在下次核验时继续存在（甚至更多）。
- **`"实测"` 标签本轮未被真正使用**（0 条）—— 因为本机可检出的条目其台账版本都与本机不符。
  标签本身保留，等将来真做逐条本机实测时启用。
- **`tools/toolset-authority.json` 随包签入**：它会随上游发布而过时，需人工重跑；
  **未接入任何自动门禁**（本仓无 CI，与 ADR-0062 的 V6 同一缺口）。
- 本次改动**尚未在运行进程生效**（插件 `dist/` 不热加载，ADR-0057）——
  不过本次改的是**构建期工具与台账数据**，运行期只影响 `note` 里的标签文字。
- T5 的 11 个 B 键里，本 ADR 只复核掉 1 个（`c.kind=*`），**余 10 个仍未复核**。
