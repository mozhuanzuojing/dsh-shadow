## Decision

### 1. 最重要的发现：`docs/adr/0004` 是一份**完整的确定性取代协议** —— 与 **D3 直接对题**

`BACKLOG.md` 的 **D3** 问的是：「是否引入 `(subject, relation, object)` 细粒度取代？」
0073 完全没提到 hl_mem 已经**就同一问题写了一篇 26 KB 的冻结 ADR**。它的答案比三元组更结构化：

**坐标是四元组，不是三元组**（`docs/adr/0004` §1 原文）：

```text
StateCoordinate(namespace, canonical_subject, canonical_slot, coordinate_qualifiers)
```

两个设计细节对 D3 直接有用：

- **`conflict_key` 只是该坐标的「持久化派生指纹和查询加速键，不是第五个独立真相」** ——
  即「派生键 ≠ 事实源」，与本仓 ADR-0003 / ADR-0051（投影不当 source）**同一条纪律**。
- **候选发现必须 exact-match 坐标**：「FTS、向量、编辑距离或模型判断**不得扩大候选边界**」。

**关系枚举冻结为六类**（`TemporalRelation` 原文）：`duplicate` / `corroborates` / `supersedes_existing` /
`historical_predecessor` / `compatible` / `needs_review`。其中两条语义值得本仓记下：

- `historical_predecessor`：**新到达的记录描述更早事实 ⇒ 只把新 claim 接为历史前驱，不反向关闭 current tip**。
  这恰好是**乱序到达**（late-arriving）这一真实场景的处置 —— 本仓 ADR-0061 的「单键 + 时间序」没有这一分支。
- `needs_review`：证明不了就**并存可见 + 记低基数 observe reason**，**不建人工队列**（§6）。

### 2. 一条可直接搬进本仓判据的原则：**错误方向不对称**

`docs/adr/0004` 的「选择原因」第 5 条原文：

> **并存噪音是可观察问题；错误关链是静默破坏。不能证明时保留多值比制造单一真相安全。**

这是本仓**尚未成文**的一条判据，且它与 ADR-0049 是**互补的一对**：

| 纪律 | 管的是什么 | 出处 |
|---|---|---|
| **缺件不静默**（本仓，ADR-0049） | **能力缺失**必须可见 | 本仓 |
| **错误方向不对称**（hl_mem，ADR-0004） | **破坏性动作**（关闭/取代/删除）必须比「留下噪音」更保守 | 本条 |

⇒ 建议写进 **D3** 与 ADR-0061 的判据面：取代是**破坏性动作**，故「宁可并存」不得被当作缺陷。

### 3. 它为**本仓既有裁决**提供了独立量化证据（这一点 0073 漏了）

本仓 ADR-0059 的裁决是「**让 LLM 判语义有硬证据反对**」；D3 也写「抽取规则必须确定性」。
hl_mem **独立走到了同一结论，并给出了数字**（`docs/adr/0004` 背景段原文）：

| hl_mem 的实测 | 读数 | 用途 |
|---|---|---|
| E1C 云端 `qwen3.7-plus` 复检 | 70 案 exact **54/70**，**2 个危险反向选择** | 模型覆盖增益不足以承担关闭 current claim 的破坏性权限 |
| 双序一致性（29 个双序案） | 仅 **21/29 = 72.4138%** | **顺序敏感性**：同一对案换个顺序结论就变 |
| v0.30.0 状态实验 | dev **13/13** → 独立 held-out r5 **仅 3/13**；**27 条错误 edge**、**3 条反例误 supersede** | 见 §4 |

⇒ **本仓 ADR-0059 的「不把语义裁决交给 LLM」不再是孤例**，而有一份**带数字的外部正例**。
**注意措辞**：这是「别家的读数支持我们的判据」，**不是**「我们验证了」。它的语料与后端与本仓不同，
**不得当作本系统的证据**（与 0073 §4 末条同一纪律）。

### 4. v0.30.0 的失败与评测治理：一处**真实**的方法论对照

**失败本身**（§3 表末行）：在**同一份 400-bundle dev** 上依次调 B2/P1/I1/Z1–Z5 与生产接线，取得 dev **13/13**，
却在**独立 held-out-r5 仅通过 3/13**。它据此**撤回了整批生产行为**（状态 prompt、admission 特许、
通用 canonicalizer、resolver），并把「不得恢复同一条『扩大提取后再靠 gate 修补』的路线」写进 ADR。

**它的对策**（`evaluation/README.md` + `docs/adr/0004` §8）：三层数据 ——
**开放 calibration（调试用，不作发布证据）** / **冻结 validation A** / **冻结 validation B**；
A、B **并行构建**、用**不同时间窗与 salt**；**「不得针对 A 修改后拿 B 当补考」**；
另有一条极强的门：**「任何 sealed/held-out 语料开始提取前，必须先运行零 LLM 的完整缝合线冒烟；命令失败时不允许烧语料」**。

**对本仓的意义（诚实评估，不建议照搬）**：

- 本仓的审计工具标定用的是**同一份夹具 + git 历史真缺陷**（`audit-wiring.selftest` / `audit-drift.selftest`）——
  这是**自证**，**没有留出集**。`tools/retrieval-eval.ts` 也没有 A/B 冻结集。
- 但**本仓规模、语料与风险面都不同**（无 CI、单机、7000+ 条自有记忆、无 LLM 写入路径），
  照搬两层 400 案冻结集**属过度设计**。
- ⇒ 落到 `BACKLOG.md` **T11**，只取**两条**与本仓同形的：① **held-out 与 dev 分离**（哪怕各 20 例）；
  ② **「烧语料前先跑零 LLM 的缝合线冒烟」**（本仓的对应物是 `npm run build` + `npx tsc --noEmit`
  已在做，但**没有「先冒烟再花代价跑评测」的显式门**）。

### 5. 它的**结果索引**里有一处罕见的诚实，值得本仓记一笔

`evaluation/results/README.md` 的公开口径表里，**它自己的结构化记忆路径低于两条对照臂**：

| 实验族 | 口径 |
|---|---|
| LongMemEval **HL-Mem** | 43/50（**86.0%**） |
| LongMemEval **full-context**（无检索上界） | 46/50（**92.0%**） |
| LongMemEval **native RAG**（raw-session 稠密检索对照） | 45/50（**90.0%**） |

⇒ **它把「自家方法低于两条对照臂」写在索引里**。这与本仓「不把缺件说成已完成」「诚实标注未验证」同源，
且比「只报自己的最好数字」更有信息量 —— 也是对本仓 **G4**（判别层未在本系统验证）态度的一个外部正例。
**同时它是一条反向警示**：**结构化 ≠ 更好**（它的结构化路径反而最低）。

另有两处口径纪律可直接对照本仓：**「不得把工程 smoke、局部重放或不同缓存的单轮结果当作正式基线」**、
**「不同提取缓存或不同 scorer 的数字不得直接横向比较」**。

### 6. `AGENTS.md` 的四条工程纪律（本仓可对照，非照搬）

| # | hl_mem 的纪律（原文要点） | 本仓现状对照 |
|---|---|---|
| ① | **测试运行预算**：「开发过程中只运行与改动**直接相关**的测试，不启用并行」；「最终候选**通常只运行一次**核心全套；**只有该次运行暴露问题并导致代码修改时，才允许第二次**」；「相同 commit 的 fast-forward 合并**复用**已有验证结果，不重复全量测试」 | 本仓 `AGENTS.md` 写「用现有 mock 测试兜底」；**本轮我为验证 4 项改动跑了 6 次全量 41 文件** —— 这条纪律本仓**有意未采纳**（规模小、全量仅数十秒），但它解释了「为什么别人不这么做」 |
| ② | **单一 CI 权威环境**：「Python 3.13 是**唯一**的 CI 权威测试环境；包的安装范围保持不变，**其他版本可安装不代表获得 CI 兼容性承诺**」 | 本仓有同类表述：「验证基线 DSH 0.1.5-rc.1 …… 更早版本未经验证，**不承诺可用**」⇒ **同构，本仓已有** |
| ③ | **状态机单一收口**：「`lifecycle.py` 是状态机守卫，**所有状态变更统一经过 `assert_transition()`**」 | **本仓缺这一收口，且这正是 T3/D4 的病根**：`lifecycleOf` 的**最前置两条判断**读**写侧** `rec.status` / `rec.pinned`，而生产**从不写**它们（`pinned: true` 全仓零处）。⇒ 若当初有此收口，「读一个没人写的状态」在结构上就无处安放 |
| ④ | **配置来源单一**：非敏感配置**只从** `hl_mem.toml` 读；「**所有 `HL_MEM_*` 环境变量均不参与 `Settings`**」；只有四个密钥走 `.env` / 环境变量 | 本仓读的是**宿主**的 `DSH_PERMISSION_MODE`（ADR-0074 定位到的那条链）—— 那是**宿主的**约定，不是本仓自造 |

**③ 是四条里对本仓最有价值的一条**（它给 D4 的既有决策补了一个**结构级**选项，见 §7）。

### 7. `capability-matrix.md` 全文：0073 漏掉的**「成熟度定义」三行**

0073 只读到前段，因而**没读到此表的定义段**。它的三档定义是**可检验的**（原文）：

- **stable**：默认主路径，**契约和降级行为受回归测试保护**。
- **beta**：已可用且有安全默认值，**仍需更多离线或生产观察**才能扩大自动化范围。
- **experimental**：显式选择后使用，**接口、质量阈值或运行边界仍可能调整**。

并对 `audit` / `observe` 给了统一定义：「会记录数据但**不自动改变核心结果或生命周期**」。
**全表 41 行**（六大特性 7 行 + 核心功能 34 行），每行六列。

> ⚠ **不要据此回改 D8 的结论**：D8 判定的是「**本仓**给自己打等级的口径不存在」——
> 该判定**依然成立**（那三行是**别家的**定义）。照搬它就是引入**外来等级口径**，
> 与 D8「用可核实代理信号」的取向冲突。**本 ADR 只登记它作为定义样本**（D8 的可选后续，非返工）。

### 8. 结构性差异（比 0073 的「补三列」更根本）

| 项 | hl_mem | 本仓 |
|---|---|---|
| ADR 数量 | **4** 篇（`0001` / `0002` / `0004`，**故意跳过 0003**） | **76** 篇（连续编号） |
| 能力矩阵 | **41 行 × 6 列**（`docs/capability-matrix.md`） | README「默认开关」表 **18 行**（v1.15.36 后） |
| 体例 | 决策集中在**少数几条** ADR + **一张大矩阵** | 决策**散在 ADR**，矩阵只做「默认开关」 |

⇒ 两种治理形态：**hl_mem = 矩阵密集 / ADR 稀疏**；**本仓 = ADR 密集 / 矩阵稀疏**。
**0073 说的「补三列」只是这个差异的表层**；真正的问题是**「此刻到底什么状态」由谁来一站式回答**。
**本 ADR 不主张改形态** —— 本仓 ADR 密集是**有意**的（每条决策可回溯），且 76 篇的量级本身是资产。

> **一处值得记的编号细节**：hl_mem 的 `docs/adr/` **故意没有 0003**，理由写在 0004 开头 ——
> 「冲突自动收敛的 ADR-0003 设计过程稿在仓库外……本决策使用 ADR-0004，**避免两个不同决策共享 ADR-0003 编号**」。
> 即：**宁可跳号，不让两个决策共用一个号**。本仓 76 篇连续无跳号，纪律一致（未出现共号）。

## Alternatives Considered

| 备选 | 否决理由 |
|---|---|
| 把结论并进 `adr/0073`，不新开 ADR | 0073 是**第一遍对标**且已接受；本轮的发现（尤其 ADR-0004 → D3）**是新决策依据**，混进旧 ADR 会让「第一遍说了什么」不可回溯。本仓 75→76 篇的体例本就是「一条决策一篇」 |
| 因此把 D3 **判为「照 hl_mem 的坐标做」** | **越权**：D3 是**待用户拍板**的决策项（三条路各有代价）。本轮只**补对照材料与判据**，**不替用户选** |
| 照搬两层 400 案冻结集 + 独立验收脚本 | **过度设计**：本仓无 CI、无 LLM 写入路径、语料是自有记忆。只取两条同形的（→ T11） |
| 用 hl_mem 的成熟度定义回改 D8 | D8 判的是「**本仓**无等级口径」，该判定成立；引入别家定义＝引入外来口径。只登记为定义样本 |
| 把 `assert_transition()` 直接实现进本仓 | 它是 **D4 的既有决策（纠正文档）之外的另一个结构选项**，而 D4 已决策。**登记对照，不推翻** |
| 采信 0073 未核的那些评测分数当作结论 | 同 0073 纪律：**未复现，不得引用为已验证**。本轮只读其**治理口径**（治理是可读的，分数不是） |

## Consequences

### 正

- 补齐 0073 明确留空的两处（`capability-matrix` 全文、评测治理），并**新增一处 0073 完全未发现的**
  （`docs/adr/0004`）——后者**直接对题 D3**。
- 为 ADR-0059「不把语义裁决交给 LLM」补上**独立量化证据**（54/70、2 个危险反向、双序一致率 72.4138%）。
- 记下一条本仓**尚未成文**的判据：**错误方向不对称**（并存噪音可观察 vs 错误关链静默破坏），与 ADR-0049 互补。
- 把 D3 的依据从「文献用三元组」升级为「**有一份完整可对照的工程实现**」，且该实现**支持本仓既有的确定性取向**。

### 负 / 已知边界

- **本轮无代码 / 行为 / 配置改动**。
- **仍未克隆、未运行、未试装**；评测分数**未复现**；`docs/superpowers/plans/`（22 篇）与
  `specs/`（11 篇）、57 个 migration、`src/` 实现**均未逐篇读**。
- §4 的评测治理**只登记两条同形可取项**，**未评估**在本仓落地的成本与收益。
- §8 的结构差异是**观察**，**不是「本仓该改成矩阵密集」的建议**。
- 「错误方向不对称」写进 D3 判据面属**建议**，D3 的决策权在用户。
