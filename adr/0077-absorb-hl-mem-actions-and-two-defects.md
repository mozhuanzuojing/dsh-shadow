- 关联 ADR：**ADR-0076**（本轮吸收的**来源**：§6 ③ 点出「本仓缺状态机单一收口」、§2 建议「错误方向不对称」、

- 版本：`1.15.38`

## Context

ADR-0076 做完 hl_mem 第二遍深读后，把可吸收项分成了三类：**登记为对照**（D3 的 `docs/adr/0004`）、
**建议成文**（「错误方向不对称」）、**落在 T11 的两条评测纪律**。用户 2026-09-12 的指令是「**能吸收哪些？做**」——
即要求把「读到的」变成「做掉的」，并**明确不要照搬**（0073 / 0076 两轮已逐条否决了 llm 抽取、向量库、
物理删除、双时间字段、resident service、成熟度等级等）。

于是本轮只做**形态可移植**的三件，并在实施过程中修掉**两处真缺陷**（都不是设计问题，是接线/判据问题）。
两处修复属「顺路发现」，但按本仓纪律**不留悬空**：发现即复现、即定性、即记账。

## Decision

### D1. 状态机**信号表 + 状态表 + 棘轮**（落实 0076 §6 ③；**移植形态，不照搬写侧守卫**）

0076 §6 ③ 记下 hl_mem 的「`lifecycle.py` 是状态机守卫，**所有状态变更统一经过 `assert_transition()`**」，
并判定「本仓缺这一收口」。本轮把缺口补上 —— 但**必须移植对的形态**：

| | hl_mem `assert_transition()` | 本仓本轮落地 |
|---|---|---|
| 防的是 | **非法迁移**（状态可被状态机写坏） | **读一条没人写的状态**（分支在生产中不可达） |
| 机制 | 写侧守卫，所有变更经它 | **声明表 + 源码级棘轮**（表在 `test/lifecycle-signal-table.test.ts`，棘轮扫**生产源码**） |
| 为什么形态不同 | 它持久化状态机 | 本仓 `lifecycleOf` 是**纯函数**（ADR-0042/0043/0051），**没有可写坏的持久状态**；取代是读时裁决（ADR-0061）。⇒ 写侧守卫在这里**无处安放**，硬加就是引入一个假闸门 |
| 为什么表**不放在 `core/lifecycle.ts`** | —— | 见下方「自曝」：表必须同时写出字段名与触发值，而审计工具的 `hasProducer` 是**文本**判据，会把表误当成**写入者**，从而使工具丢掉真线索 |

**表（唯一声明源）**：8 个信号，每个必须回答「**触发它的那个值，生产代码写不写得出来**」：
`derived`（有写入者/调用点）/ `external`（**写不出来**，保留给外部人工或夹具，`why` 必须写明理由）。
其中 `external` 三条正是 T3 / D4 的病根：`pinned: true`（生产只写 `false`）、
`status: "archived"`、`status: "superseded"`（生产只写 `active` / `compacted`）。

**棘轮**（`test/lifecycle-signal-table.test.ts`，4 组，全绿）：

| 组 | 断言 | 判据来源 |
|---|---|---|
| ① | `lifecycleOf` 里读的 `rec.<字段>` 集与信号表声明集**双向完全一致** | 源码扫描 + 注释剥离复用 `audit-drift.lib.ts` |
| ② | 3 个 `external` 信号在生产里**零写入者** | **复用已标定的 `hasProducer`**（它先删比较表达式，否则读点冒充写入点） |
| ③ | `derived` 的字段信号在生产里**确有赋值点**；3 个参数信号确有**调用点接线**（`query/query.ts` 真的传了 `v.superseded`） | 窄赋值正则 + 读/写正控 |
| ④ | 8 个状态与实现**互满**，每个状态都能被正控产出，且行为测试逐条覆盖 | `lifecycleOf(...)` 实调用 |

**三处必须写明的实现细节**（都是本轮踩出来的，不是装饰）：

1. **声明表刻意放在测试面**（本轮自曝，见下）。
2. **`hasProducer` 只认字符串字面量**，`pinned: true` 是布尔 ⇒ 另用窄判据 `\bpinned\s*[:=]\s*true\b`，
   并配正控（喂 `pinned: true` 必须检出）。
3. **棘轮不是恒真的空话**：②③④ 三组都带**反例/正控**（真写入者必须被检出、读表达式不得被当赋值点、
   状态必须能真的产出来、「表放生产面必然误报」的自曝正控）。

#### ⚠ 自曝：这张表**最初写在 `core/lifecycle.ts`**，被工具自检挡下

第一版的表放在生产文件里（"让状态机声明自己的信号"读起来更自然）。**把工具自检纳入门禁后立刻变红**：

```text
AssertionError: 工具应报出已知的 status=superseded（本轮确证的无写入者分支）；
实际 keys=[...]   ← 列表里没有 status=superseded
```

**机制**：表必须同时写出**字段名**（`field: "status"`）与**触发值**（`literal: "superseded"`），
而 `hasProducer` 的判据是「同一行内字段名与字面量在 200 字符窗口内共现」⇒
**表本身被当成了写入者** ⇒ 审计工具从此**丢掉 `status=superseded` 这个真线索**。
（这与 `hasProducer` 标定测试③抓的「读点冒充写入点」是**同一个误报机制**；
`core/lifecycle.ts` 里 `rec?.status === "superseded"` 这类**比较式**被 `stripCmp` 正确剔除，
所以它原本才被判「无写入者」。）

**为什么不是「改工具去迁就格式」**：给工具加一条「`core/lifecycle.ts` 除外」是把**特例**写进通用判据，
会随文件演进腐化，并掩盖该文件里**真实**的写入者。**为什么不是「换个写法绕开正则」**：
那是靠**格式**维持语义正确性，一次 prettier 重排就静默失效。

**采纳的修法**：**声明转移出生产面**。理由不是「为了变绿」，而是三条独立成立的理由：
① 这张表**唯一的消费方就是棘轮**（属**测试断言**，不是运行时数据）；
② 它留在生产面会被 `audit:wiring` 的 A 段判成「仅测试消费」的零引用导出（与 T4/T10 同族噪音）；
③ 移出后**无需任何文件排除**，判据回到「生产面就是生产面」。
**强制力不变**：棘轮①③扫的仍是**生产源码**（`lifecycleOf` 的函数体、生产里的赋值点/调用点）。
`core/lifecycle.ts` 留一段指向棘轮的**注释**（注释会被 `hasProducer` 的 `stripComments` 剔除，不产生误报）。

> 这条值得单独记一笔：**是审计工具自己的自检挡住了「对审计工具的一次回归」**——
> ADR-0070 造这把工具时的标定投入，在本轮直接变现。

### D2. 前置冒烟门：`npm run verify` 从「工具类型门」升级为**完整确定性缝合线**

0076 §4 记下 hl_mem 的门：「**任何 sealed/held-out 语料开始提取前，必须先运行零 LLM 的完整缝合线冒烟；
命令失败时不允许烧语料**」。本仓对应物**长期不存在**：

| | 改前 | 改后（v1.15.38） |
|---|---|---|
| `verify` | `typecheck:tools`（**只有工具面的类型门**） | `typecheck:tools` + `tsc --noEmit`（**插件面**）+ `test:all` |
| `test:all` | **不存在** | `npm run build && node tools/run-tests.ts` |
| 覆盖 | 插件自身**未类型检查**、**未构建**、**未跑任何测试** | 编译 + **43 个行为测试** + **2 个工具自检** |

**新增 `tools/run-tests.ts`**（含三条设计取舍，均写进文件头注释）：

- **每文件一个子进程**（不用同进程 `await import()`）：插件在模块级注册表上有全局副作用，
  同进程串跑会互相污染 ⇒「单跑绿、全跑红」的假红/假绿。
- **`stdio: "inherit"` 而非管道**：受约束沙箱下 pipe 会被拒（EPERM），inherit 不会；且失败时输出原样可见。
- **`test/*.test.ts` + `tools/*.selftest.ts` 同批**：这把 **V6「审计工具未接入任何自动门禁」从「靠人记得跑」
  变成「门禁里就有」**（`audit:wiring` / `audit:drift` 的**报告**本身仍未进门禁 —— 它们是人工分诊工具，
  退出码语义未定义，见 `BACKLOG.md` V6 的更新）。

> **这道门当轮就交付了价值**：它第一次运行时立刻抓到 `recall-attribution.test.ts` 失败 ——
> 而该失败**在干净 HEAD 上同样存在**（已用 worktree 复现），即「本仓全绿」这个既有结论**当时是错的**。

### D3. 「错误方向不对称」写成文（0076 §2 只到「建议」）

0076 §2 把 hl_mem `docs/adr/0004` 的这句话列为「本仓尚未成文的一条判据」：

> **并存噪音是可观察问题；错误关链是静默破坏。不能证明时保留多值比制造单一真相安全。**

本轮让它成文，落在**三处**（避免只写在一处又漂移）：
`CONTEXT.md`（共享语言，因为它是**术语级**判据）、`adr/0061` 的补记（取代语义的判据面）、
`BACKLOG.md` D3 的判据面（待决策项的对照材料）。**不替用户做 D3 的决策。**

### D4. 顺路修掉的两处真缺陷

#### D4.1 consolidated 文件的 `time` **两条读路径两套值**（ADR-0069 同族第 3 例）

**复现**（实证，非推断）：

- 写侧（本进程缓存）：`core/writer-materialize.ts` 用 `ep.startedAt.slice(11,17).replace(/:/g,"")`。
  `core/episode.ts:49` 声明格式是 `YYYY-MM-DD HH:MM:SS` ⇒ `slice(11,17)` = `"09:00:"` ⇒ `"0900"` ——
  **4 位、根本不是 HHMMSS**（全仓其它记忆的 `time` 都是 6 位）。
- 读侧（重启后磁盘重扫）：`persistence/files.ts` 从**文件名**反解 `^\d{4}-\d{2}-\d{2}--(\d{6})`，
  而 consolidated 文件名是 `ep-<id>-consolidated.md`（**不含时间戳**）⇒ `time = ""`。

**为什么这不是「显示不准」**：`time` 是**取代裁决**的输入（`query/query.ts:299` → `observer/arbitrate.ts:63`），
裁决决定打分（×0.7，`:301`）与生命周期标签（`:308`）。`arbitrate.ts:63` 是**严格** `t < newest` ⇒
两个**同日同 `entry`** 的 consolidated 文件在磁盘路径上**并列**，谁都不被判取代 —— 而较早的那个**应当**被取代。
⇒ 同一份语料，**本进程与重启后给出不同裁决**。

**修法（判据收一处，而不是两处各修一遍）**：`persistence/files.ts` 导出 `timeFromName`（读侧反解，
唯一正则源）与 `memoryFileName`（写侧造名）；写侧的文件名带 `<date>--<HHMMSS>-`，
缓存里的 `time` **由文件名反解**（`timeFromName(name)`）⇒ 两侧**同源**、结构上不可能再分叉。
**向后兼容**：无时间戳的旧文件仍被枚举（`time = ""`、不崩）。

**测试** `test/memory-time-single-source.test.ts`（5 组，全绿），关键是**反例正控**：
断言修前形态（两个空 `time`）**确实漏判取代**，证明「早者被取代」不是恒真。

#### D4.2 一颗**已在本地零点引爆的时间炸弹**（`recall-attribution.test.ts` 场景 30）

**现象**：场景 30 要逐个暴露 8 个生命周期状态，`OBSERVED` / `VERIFIED` / `TRUSTED` 全缺。

**根因（可核对，非推断）**：

1. `query/query.ts:276`：`stale = ageDaysOf(rel) >= staleDays`，`staleDays` 默认 **7**；
2. `core/lifecycle.ts` 里 `if (stale) return "DECAYING"` **排在** `hits>0 → OBSERVED` /
   `confirms>=1 → VERIFIED` / `confirms>=2 → TRUSTED` **之前**；
3. fixture 硬编码日期 **`2026-09-05`**；
4. `core/util.ts:4` 的 `today()` 用**本地**日期（`getFullYear/getMonth/getDate`），而 `ageDaysOf` 减的是它。

⇒ 本机 **本地日期 2026-09-12（UTC+8）而 UTC 仍是 2026-09-11** ⇒ age = **7** ⇒ `7 >= 7` ⇒ `stale = true`
⇒ `DECAYING` 整片盖掉那三个状态。**这颗炸弹在本轮工作当天本地零点引爆**。

**修法**：fixture 日期改为**相对今天**（`today()` / `today(30)`），并显式写出 `retention: { staleDays: 7 }`。
⇒ 测试从「必须在一个 7 天窗口内被跑过」变成**时间无关**。

**这是一类问题，不是一处**（⇒ 新开 **T12**）：全仓 `test/*.test.ts` 里硬编码日期的**风险面**已扫出清单
（`2026-09-01` … `2026-09-12` 共 12 个日期、跨 8 个文件），**但只有场景 30 被确认与 `stale`/age 判据耦合**；
其余需逐个判定（清单是**风险面**，不是已确认的 43 处炸弹）。
**没被发现的原因正是本轮 D2 要解决的那件事：此前没有一条「把全部检查跑一遍」的命令。**

## Alternatives Considered

| 备选 | 否决理由 |
|---|---|
| 照搬 `assert_transition()` 写侧守卫进本仓 | 本仓 `lifecycleOf` 是**纯函数**，没有可写坏的持久状态；硬加一个不拦任何东西的守卫就是**假闸门**（本仓反复记录的缺陷类型）。⇒ 移植**形态**（声明 + 断言）而非**位置** |
| 给 `pinned` / `archived` / `superseded` 补上生产写入者，让状态「真的可达」 | **越权**：D4 已决策「纠正文档 + 不再加写入者」，且取代是读时判断、持久化会随可见集失效。本轮只**把不可达写成机器可核的事实** |
| 信号表只写在注释里（像原来那样） | 散文**不会在漂移时报警**。本仓已四次踩同一族缺陷（ADR-0063 / D5 / 0070 T5 / 0062 盲区） |
| 棘轮用自己写的正则判「有无写入者」 | 已有**标定过**的 `hasProducer`（它解决过「读点冒充写入点」）。另写一份＝把同一条判据又表达一次（ADR-0063） |
| **把声明表放在 `core/lifecycle.ts`**（本轮第一版方案，被工具自检挡下） | 表必须同行写出字段名与触发值 ⇒ `hasProducer` 把**声明当写入者** ⇒ 审计工具**丢掉 `status=superseded` 真线索**。改工具去迁就＝往通用判据里塞特例；换写法绕正则＝靠格式维持语义（一次 prettier 重排即静默失效）。⇒ 表移到测试面，**强制力不变**（棘轮扫生产源码） |
| 把「表放生产面」这条教训只写进提交信息 | 提交信息不进文档；这条是**判据级**取舍（工具是文本判据、声明是文本），写进 ADR 才能被后来者复用 |
| `test:all` 用同进程 `await import()` 串跑全部测试 | 插件有模块级全局副作用 ⇒ 互相污染 ⇒ 假红/假绿。用子进程隔离 |
| `verify` 里加 `audit:wiring` / `audit:drift` **报告**本身 | 它们是**人工分诊**工具，输出是线索清单（不是通过/失败），退出码语义未定义 ⇒ 硬塞进门禁只会制造噪声跳过 |
| 让 `verify` 跑 `git` 状态 / 版本号等检查 | 与「零 LLM 的**缝合线**冒烟」无关，属另一类闸门（发布门）。**不混** |
| 顺手把全仓 12 个硬编码日期全部改成相对日期 | **越界且无从验证**：只有场景 30 被确认与 age 判据耦合；改动其余 11 处属**未经复现的改**。⇒ 记 T12，附已扫出的风险面 |
| 把 `historical_predecessor`（乱序到达）一并吸收 | **越权**：那是 **D3 的决策范围**（是否引入细粒度取代），用户尚未拍板 |
| 顺带引入 hl_mem 的成熟度等级 / 冻结语料 / LLM 抽取 | 0073 / 0076 已逐条否决；本轮**判据不变**（等级＝外来口径；冻结语料待 T11① 的语料决策；LLM 抽取违 ADR-0059） |

## Consequences

### 正

- 补上 0076 §6 ③ 指出的结构缺口：**「读一条没人写的状态」现在会在结构上被报警**，且证据是机器核的，
  不是散文（3 个 `external` 信号的零写入者声明已被 `hasProducer` 核实，并带正控）。
- **一次被挡下的自我回归**：本 ADR 第一版把声明表放进生产文件 ⇒ 审计工具**丢掉 `status=superseded` 真线索**
  ⇒ 被 `tools/audit-wiring.selftest.ts` 立刻挡下。ADR-0070 造工具时的标定投入在本轮**直接变现**。
- 本仓第一次有了**一条命令跑完全部确定性检查**（`npm run verify`：编译 + 43 行为测试 + 2 工具自检）。
  **它当轮就抓到一个既有失败**（`recall-attribution.test.ts`，干净 HEAD 上同样红）——
  「本仓全绿」这个既有结论当时是**错的**。
- 「错误方向不对称」成文（术语级 + 判据级 + 待决策级三处），D3 的对照材料补齐。
- 修掉一处**跨重启裁决会变**的真缺陷（consolidated `time` 两侧分叉），且修法是**判据收一处**
  （写侧从文件名反解），结构上不可能再分叉；`time` 的分歧现在有独立测试（含反例正控）。

### 负 / 已知边界

- **T12 是新开的欠账**：全仓硬编码日期 fixture 只拆了**已引爆的那一颗**；其余 11 处（风险面清单见 D4.2）
  未逐个判定是否与 `age` / `stale` 判据耦合。
- **`compact.enabled` 默认关**（`core/types.ts`）⇒ D4.1 修的那条路径在默认配置下不会被走到；
  修复的价值在于**一旦打开就正确**（以及消除了一个「同族第 3 例」的判据分叉）。
- **`audit:wiring` / `audit:drift` 的报告本身仍未进门禁**（V6 只**部分**接入：自检进了，分诊报告没进）。
- **棘轮的边界**（测试内已诚实标注）：只核**本仓库源码** —— 别的会话/外部工具直接改 `_meta.json`
  塞入 `pinned: true` 这类**运行时**事实扫不到；`lifecycleOf` 内部的**优先级顺序**也**未**由表表达。
- **`verify` 会写 `dist/`**（它含 `build`）。这是刻意的：测试 import 的是 `dist/`，不构建就会测到旧产物；
  但代价是「跑门禁」会改工作区（需在提交前注意 `dist` 状态）。
- D4.1 的**端到端**（召回渲染里较早的 consolidated 显示为 `裁决 superseded`）**未单独断言**，
  只断言到「文件名 / 磁盘反解 / 裁决函数」这一层（测试内已标注）。
- 本轮**未**吸收 `historical_predecessor`、冻结语料、成熟度等级（理由见上表）；0073 / 0076 的**不吸收清单不变**。
