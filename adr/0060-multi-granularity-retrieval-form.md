# ADR-0060: 多粒度检索层的形态（**路由已存在**；不做无阈值全量扇出；多粒度用「单索引+层级表示」）

- 状态：**已接受（技术判据部分）· 待用户裁决（产品方向部分）**
- 决定日期：2026-09-11
- 关联 ADR：**ADR-0001**（投影文件树而非向量库；其 **Notes 留了口**：「若日后召回不足，可在 `_index.md` 之上叠一层向量检索作为增强，而不推倒文件树」）、**ADR-0054**（Semble 作为 Index Engine 第三候选 provider，**检索层非裁决层**——本 ADR 是其延伸）、ADR-0043（Shadow Contract：Atom/Projection/Evidence/Mutation）、ADR-0049（缺件不静默）
- 关联术语：`../CONTEXT.md`（Index Engine / 候选生成 / provider）
- 版本：`1.15.16`

## Context

用户 2026-09-11 的设想：**「向量化库多弄几个，片段超大、大、中、小等，每次找回从这些库中都找一遍。」**

动手前先做了三件事：

### ① 文献裁决（调研）

| 方向 | 证据 |
|---|---|
| ⚠️ **全量扇出被产业级实测击穿** | Scaling RAG with RAG Fusion（[2603.02153](https://arxiv.org/abs/2603.02153)，2026-03）：融合**确实**提高 raw recall，但「增益在重排与截断之后基本被抵消」，企业知识库 Top-k **打不过单查询基线**，若干配置 **Hit@10 0.51→0.48**，并引入额外延迟 |
| ⚠️ **强单检索器/重排器主导** | Beyond the Reranker（[2606.28367](https://arxiv.org/abs/2606.28367)，2026-06）：有强 cross-encoder 在场时，**层级摘要 / 图扩展 / 路由 / rank fusion 全部无可靠增益** |
| ⚠️ **噪声有害** | Lost in the Noise（[2601.07226](https://arxiv.org/abs/2601.07226)，2026-01）：干扰物致性能最多降 **80%**；原文点名 *"agent workflows often amplify these errors by over-trusting noisy tool outputs"* |
| ✅ **路由优于扇出** | LTRR（[2506.13743](https://arxiv.org/abs/2506.13743)）、Retriever Portfolios（[2605.31176](https://arxiv.org/abs/2605.31176)）、Mix-of-Granularity（[2406.00456](https://arxiv.org/abs/2406.00456)）——**后者立论前提与用户相同**（固定策略导致信息利用不足），但解法是 **router 按查询选粒度**，不是全查 |
| ✅ 块大小**没有单一推荐值** | [2505.21700](https://arxiv.org/abs/2505.21700)（64–128 token 事实型 / 512–1024 需广上下文，且不同嵌入模型偏好相反）；[2601.14123](https://arxiv.org/abs/2601.14123)（~2.5k 上下文悬崖、overlap 无收益） |
| ✅ 每来源**各自**标定阈值 | 2606.28367 的有效方法 SSCC = 「为**每一个 score source 设一个单独的接受阈值」**，且只在异构数据上有效 |

**调研的两处诚实标注**（必须原样保留）：
- 「无阈值检索器 + 扇出会怎样」**没有直接实证论文**——是把「噪声有害」与「无阈值 ⇒ 必返 top-k」两条组合**推理**出来的。**故本 ADR 不引它当结论，改为自己测量（见下）。**
- 「small-to-big / parent-document / auto-merging retriever」**没有原始论文**（那些名字来自 LangChain 工程文档）。学术等价物是 RAPTOR、HiChunk/Auto-Merge、UMG-RAG、HeteRAG。**引用时别引「small-to-big 论文」。**

### ② 本系统真语料上的实测（新增 `tools/retrieval-eval.ts`）

把上面那条「组合推理」变成**测量**：语料 = 真实 `.shadow`（1500 条等距取样），检索器**按 ADR-0054 已实测的性质建模**（Semble **无阈值、无负信号**：语料里没有的话题照样返回最高分），**同候选预算**、多种子（报极差）。

| 策略 | recall | nDCG | 均返回 | **离题噪声** |
|---|---|---|---|---|
| A 单库·词·**有阈值** | **0.358**±0.033 | 0.267 | 3.57 | **0.000** |
| B 单库·词·**无阈值** | 0.358 | 0.267 | 5.00 | **1.000** |
| C **扇出2库·无阈值**+RRF（用户设想） | 0.347±0.053 | 0.265 | 5.00 | **1.000** |
| D **路由·有阈值+弃权** | **0.358** | 0.267 | 3.57 | **0.000** |
| E 扇出2库·有阈值+RRF | 0.347±0.053 | 0.265 | 5.00 | 1.000 |
| F 单库·二元组·有阈值 | 0.344±0.060 | 0.254 | 5.00 | 1.000 |

**四条读数**：
1. **「无阈值」这一个性质就足以让离题查询灌满噪声**（B = 1.000 vs A = 0.000），与库数无关；扇出只是把它**乘以库数**。
2. **扇出（即便含互补来源）没换来召回**：E 0.347 vs A 0.358（**-0.011，更差**）；对单·二元组仅 +0.002，落在 ±0.053 的种子极差内 → **不显著**。与 2603.02153 的「增益被抵消」一致。
3. **阈值强弱因检索器而异**（二元组 F 噪声 1.000 vs 词检索器 A 0.000）→ 这是「每来源各自标定阈值」（SSCC）的实证依据。
4. 最差即**无阈值扇出**：召回不升（0.347 vs 0.358）· 噪声 1.000 · 预算 5.00 条/查询。

### ③ **现有实现已经是「路由」，不是「扇出」**

这一条改变了整件事的性质，必须点明：

```
core/types.ts:35    indexEngine?: { provider?: "fs" | "zg" | "semble" }   ← 单值
core/index-engine.ts:47   const provider = config?.indexEngine?.provider || "fs";
                          if (provider === "zg") { ... }
                          if (provider === "semble") { ... }
                          return { ...fs 默认 }
```

**工厂按配置路由到恰好一个 provider，没有扇出。** 故用户的设想**不是「从无到有加能力」，而是对现有设计的退步**。

## Decision

### 1. **不做**无阈值全量扇出（技术判据，证据充分）

三条理由各自独立成立：① 实测噪声拉满且召回不升；② 预算多耗；③ 与现有单 provider 路由相比是退步。

### 2. 「多粒度」若要建，形态是**单索引 + 层级表示 + 路由**，不是「建 N 个库」

依据 RAPTOR / HeteRAG / UMG-RAG（学术等价物）：
- chunk 带 `level` / `parent_id`，**只索引最细层**，命中后沿 parent 上取；
- 收益来自「表示」，不来自「库数」——**库数增加的是噪声面，不是信息面**；
- 块大小**无单一最优**（2505.21700 / 2601.14123 结论相反）→ 正因如此才需要**按查询选粒度**，而不是并行建多份。

### 3. 加**判别层**的优先级高于加库

2606.28367：强重排器承担流水线绝大部分质量。有它在场时其它增强无可靠增益。⇒ **先重排，再谈多库。**

### 4. 路由优先用**简单基线**，别一上来训模型

2607.24010：简单检索分数/不确定性基线常与学到的效用路由器相当。

### 5. 若将来仍要多来源，**每个来源必须各自标定阈值**

实测 ③ 已证「阈值强弱因检索器而异」；SSCC 是文献侧的同向结论。**无阈值来源不得参与融合**（会把噪声按构造注入）。

### 6. 保留 ADR-0001 / ADR-0043 / ADR-0054 的定位不变

向量层仍是 ADR-0001 Notes 说的**增强层**、ADR-0054 说的**检索层（非裁决层）**。`Atom=source` / `Projection 可重建` / `Evidence 可追溯` / `LLM 不造事实` / **无证据不返回** 五条不变量未动。

## 落地核实（v1.15.18 补）：证据支持的形态**本仓已实现**

ADR 只给「该做成什么样」是不够的，故逐条核实本仓现状：

| 证据支持的三要素 | 本仓实现 | 位置 |
|---|---|---|
| **① 单索引 + 路由到**一个**来源** | ✅ `indexEngine.provider` 是**单值**（`"fs"｜"zg"｜"semble"`），工厂只返回一个 provider | `core/types.ts:35`、`core/index-engine.ts:47` |
| **② 层级表示**（按内容分层，不是建多份） | ✅ `tierFor` 派生 `L0/L1/L2`：有思考/结论 → `L2`；动作行占比 >0.6 → `L0`；否则 `L1` | `retrieval/rank.ts:136-144` |
| **③ 命中后沿层级展开**（parent promotion 的等价物） | ✅ `renderByTier` 按预算逐层放：**L0 只给摘要 → L1 加命中片段 → L2 加正文骨架**，且受 `budgetChars` 约束 | `retrieval/render.ts:54-78` |

⇒ **「多粒度」这一形状（超大/大/中/小 的等价物）已经在跑**，且是**单索引 + 层级**、不是「建 N 个库再全查」。
故 ADR-0060 §2 的建议不是「改造」，而是**确认现有形态正确、并明确拒绝退化为全量扇出**。

**仍缺的部分**（若要继续按证据往前推）：
- 判别层（重排器）—— 本仓无重排器，「先重排」的建议**引自文献、未在本系统验证**；
- 路由的**显式化**：现在路由是**配置级**（选一个 provider），而文献里的 router 是**按查询选**粒度/来源
  （Mix-of-Granularity 的形态）。本仓的「按预算逐层展开」是**检索后**的粒度控制，与**检索前**的路由不是一回事。
- `(subject, relation, object)` 级细粒度取代（ADR-0061 §负 已记）。

**产品方向仍待用户裁决**（本 ADR 不替用户决定「要不要引入真实向量库」）。

## 待用户裁决（不得由本 ADR 单方面决定）

用户原话是「**每次找回从这些库中都找一遍**」，本条被实测与文献**双重反对**。这是**产品方向**，须由用户拍板：

| 选项 | 含义 |
|---|---|
| **1. 按证据改**（推荐） | 维持现有单 provider 路由；多粒度做成「单索引 + 层级表示」；先加判别层 |
| **2. 先做小实验** | 用 `tools/retrieval-eval.ts` 在真机装 semble 后复测，拿自己数据再定 |
| **3. 仍按原设想** | 接受噪声放大；本 ADR 记录「用户决策，证据反对」，不改 ADR-0001/0043 |

**本 ADR 未单方面推翻任何既有 ADR**；它只补上「多粒度该怎么做」这一层，并把冲突**显式提请用户裁决**。

## Alternatives Considered

| 备选 | 否决理由 |
|---|---|
| 建 N 个向量库、每次全查 | 实测：噪声 0.000→1.000、召回 -0.011、预算 +1.43 条/查询；文献同向反对 |
| 多粒度 = 建 N 个独立索引 | 收益来自**表示层级**而非索引数量；RAPTOR/HeteRAG 均用单索引+层级 |
| 在无阈值来源上做 RRF 融合 | 无阈值 ⇒ 必返 top-k ⇒ 按构造注入噪声（实测 B/C 均 1.000） |
| 只加库、不加重排层 | 2606.28367：有强重排器时其它增强无可靠增益 → **顺序反了** |
| 把评测做成 ratchet 测试锁死数值 | 输入是**活的** `.shadow` 语料（随时间变），锁数值必然 flaky。故做成**测量工具**而非测试 |

## Consequences

### 正
- 把调研标注为「属组合推理、非论文结论」的那条**变成了本系统真语料上的测量**——这正是调研指出的文献空白（「无阈值 + 扇出」无直接实证）。
- 补上了「多粒度该怎么做」的形态（单索引 + 层级 + 路由 + 各自阈值），有学术等价物可引。
- **点明了一个容易被忽略的事实**：现有实现已是路由，扇出是退步——避免把「加能力」误当成「改架构」。
- `tools/retrieval-eval.ts` 可复用：装 semble/zg 后可直接复测，无需重写。

### 负 / 已知边界
- 检索器是**按已实测性质建模**的，**不是**真实向量模型；本机 semble / zg 均未安装（ENOENT），**未跑真实向量检索**。
- 查询是「部分线索」式（3 个 token），**不是自然语言问句**；recall 绝对值（0.358）只在本设定下有意义，**不可外推**。
- 只测了 RRF 一种融合（另有凸组合 CC，文献称可能优于 RRF），未对照。
- 未测「重排层」的增益（本仓无重排器）—— 故「先重排」的建议**引自文献，未在本系统验证**。
