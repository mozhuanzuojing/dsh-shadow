### §A 的由来：三个开关一直默认关，而它们正是第 2 句要的东西

`retention` / `forget` / `compact` 自 `v1.9.0`（`forget` / `compact` 更早）起**默认关**。默认关有两层后果：

- **能力层** —— 装完什么都不动 ⇒ 索引与召回**不收口**。真工作区实测（2026-09-15，探针见 §E）：
  `.shadow/_index.md` **2 251 348 字节（2199 KiB）/ 24 639 行 / 6 个 `## ` 段**，底下 **8310 条记忆 / 7 个日期目录**
  ⇒ 索引每次重建都是**全量重写**，每次入口读都要背它。
- **纪律层（更根本）** —— 判据是**三个开关各写一遍 `=== true`**（外加一个只读 `forget.enabled` 的 `maxActive` 闸门，
  共四处）。这与 `adr/0084` 修掉的那一族**同源**：**把「未传」与「显式关」混为一谈**。
  更刺眼的是它和本仓另一条已立的判据**方向相反**：`v1.15.35` 给 `abstracts` 论证「**默认关等于又一次
  『写好了但从不执行』**」并因此默认开；而三个量控开关——第 2 句要的那三件——仍是默认关。

### §B 的由来：同一个工具的两个分支，一个有预算、一个没有

`max_tokens` 此前**只作用于带 `topic` 的路径**。无参路径（读目录 = agent 的**第一跳**）把 `_index.md`
**整篇原样**返回。按上面的实测，那是一个 **2.2 MB** 的返回值，而同一个入口在带 `topic` 时
既有预算又有**截断信封**。这是 `adr/0084` 那类判据分叉的**变体**：不是两份实现不一致，
而是**同一处的一个分支忘了接预算**。

## §A 决定：「默认开」的判据收一处，默认值翻成开

### A.1 判据（只此一处）

`core/util.ts` 新增：

    export const onByDefault = (v: unknown): boolean => v !== false;

`undefined` = **开**；**只有显式 `false`** 才关。理由与 `numOr` 同族：把「**未传**」与「**显式关**」分开 ——
这是 `adr/0084`「显式 0 ≠ 未传」的**布尔版**。

**四处读取点全部改走它**（这是本片与「只改默认值」的区别：改默认值只是 3 个字面量，
而判据仍然散在四处、下次加开关还会各写一遍）：

| # | 位置 | 改前 | 改后 |
|---|---|---|---|
| 1 | `core/forget.ts` 的 `isForgettable` | `cfg.enabled !== true` → false | `!onByDefault(cfg.enabled)` → false |
| 2 | `core/writer-materialize.ts` 的 `compact` 闸门 | `core.compactCfg.enabled !== true` | `!onByDefault(core.compactCfg.enabled)` |
| 3 | `core/writer-materialize.ts` 的 `maxActive` 闸门 | `core.forgetCfg.enabled === true` | `onByDefault(core.forgetCfg.enabled)` |
| 4 | `core/writer-materialize.ts` 的 `registerMeta` | `core.retentionCfg.enabled === true` | `onByDefault(core.retentionCfg.enabled)` |
| 5 | `query/query.ts` 的 `retention` 排除分支 | `retentionCfg.enabled === true` | `onByDefault(retentionCfg.enabled)` |

第 3 行值得单独说：它**不在**三个「开关」的名单里，只**读** `forget.enabled`。
不改它则出现一种**半开**形态 —— `isForgettable` 默认开、而硬上限 `maxActive` 默认失效；
即「开关开了，它的一个子能力默认睡着了」。**这类「同一个键在另一处各判一遍」正是本仓两次
代价明确的教训**（`tools/comparison-points.lib.ts`、`core/util.ts` 的 `numOr`）。

### A.2 方向的语义：权限轴的读法随之改变

改之前是「**用户要求才启用**」；改之后是「**关掉才是用户的显式动作**」。这不是修辞 ——
它决定 README 权限轴那一行怎么写、也决定 §C 的边界 ④ 判成什么。⇒ README 同步改了：
默认开关表的引子不再枚举「默认开的是哪几项」（**那是能推出来的数，不手写**），改为**只给两条方向的读法**。

### A.3 边界（四条，都不是「顺带发现」，是决定）

1. **默认开 ≠ 不写工作区**。这三个开关**都会写**：`retention` 建 `_meta.json`、`forget` 移出活跃集、
   `compact` 写 `-consolidated.md`。⇒ README 那句「**会写、会烧 token 的增强默认都关**」**不再成立**，
   已改写（它与「只读工具不写工作区」是两句不同的话，后者仍成立）。
2. **不减磁盘占用（这条被反复问到，必须写死）**：`Forget ≠ Delete`（ADR-0031）—— 被遗忘的记忆**文件仍在**；
   收口**不删原子**（`compact` 产出 consolidated 而原子保留可回放）。⇒ 三件套缩的是**活跃集 / 索引**，
   **不是文件数、不是磁盘占用**。要减磁盘占用必须另有动作（本版**不做**，也没有把它写进任何承诺）。
   已由 `test/volume-defaults.test.ts` 的第 ③④ 组**正面断言**（「文件仍在」而非「只断言不在召回里」）。
3. **风险面被放大，如实标注**：`ADR-0067` 的 `minHits` 保护链与 `ADR-0068` 的 `runCompact` delta
   **真机未验**，而它们此前挂着「默认关 ⇒ 不执行 ⇒ 风险为零」。翻成默认开后，**这两条从「未验证」变成
   「未验证且在生产路径上」**。本版**不因此撤回默认全开**（用户决定），但把这条写在这里，并**不**给它配
   「已验证」的说法 —— 它仍是**未验证项**。
4. **「显式关掉不留痕」这个裁定的适用范围变清楚了**：README 默认开关表里 `retention` 那格一直标着
   ⚠️**静默**（「关闭 ⇒ 差异不可见」）。`adr/0085` 的裁定是「**用户显式 `enabled:false` 不留痕**——
   关掉是用户的选择，渲染成告警＝把读者的决定当故障」。默认关时这两条**互相矛盾**（关是默认态，不能说是用户的选择）；
   默认开后**它自动成立**：那一格现在描述的只可能是**用户显式关掉**之后的样子 ⇒ 该格**不再是候选缺陷**，
   只是一句如实的后果说明。README 已就地改口径（不再拿它当 T8 的待办）。

### A.4 为什么是「默认开」而不是「默认开 + 首次运行写一次配置」

写默认配置文件会引入**第二份默认值**（配置文件里的数 vs 代码里的数），正是本仓反复清理的
「判据两份实现」。⇒ 坚持**单一判据**：代码里一处 `onByDefault`，配置里不落盘任何默认值。

## §B 决定：无参路径与 `topic` 路径共用同一份预算

### B.1 判据

`query/query.ts`：把 `max_tokens` 的解析与钳位**提到分支之前**（默认 `1600`，钳在 `[256, 8000]`），
无参分支改为 `renderIndexBudgeted(idx, maxChars)`（`retrieval/render.ts`）。

### B.2 `renderIndexBudgeted` 的四条判据（与 `truncationNote` 同族，但**不是**复用它）

| # | 判据 | 为什么不能省 |
|---|---|---|
| ① | **结构感知** —— 按 `## ` 段整段装，**不腰斩行内** | 索引是给人/agent 读的 Markdown；半个链接、半行路径比「少一段」更糟 |
| ② | **按段名 + 行数披露**丢掉的段（`> 未返回的段：…(N 行)`），装不下整段时标 `> 部分返回的段：` | 截断必须自报（ADR-0049）；且**点名**才能让读者判断「少的那段要不要穿透取回」 |
| ③ | **放得下就零多余文字** | 索引在预算内时**逐字原样**返回，不加任何信封（否则每一次入口读都背上几行噪音） |
| ④ | 连第一行都放不下 ⇒ **按字符硬截断并自报**（`已按字符硬截断`） | 不假装那是完整段；也不返回空 |

**为什么不复用 `truncationNote`**：`truncationNote` 的输入是**召回命中集**（条数、命中/返回/冷却），
而这里的输入是**一篇文档**（段、行）—— 两者的「丢了什么」不是同一种可数结构。
强行合并会让判据变成「看情况」；**分两份、各自说清口径**才是本仓要的（`adr/0063` 判据收一处 ≠ 判据合并）。
⇒ 已落一条：`renderIndexBudgeted` 与 `truncationNote` 的**信封形状必须一致**（`> 下一步：`、
`> 未返回的…：`），因为它们会在**同一个返回值里同时出现**（`read_shadow(topic)` 与无参路径）。

### B.3 边界

- **信封本身不计入预算**（与 `recall` 那条已知边界同源，README 已写）；因此超预算返回会比 `maxChars` 多出几行。
  测试因此断言的是**两条**：返回正文字数 ≤ `max_tokens × 4`，且**整体**长度 ≤ `maxChars + 1200`。
- **预算必须被基本用满**：测试断言 `rIdx.length >= maxChars × 0.8`。这不是洁癖 —— 第一版实现的实测结果
  是「预算 6400 字、只返回 1260 字」（把整段装不下就整段丢），**浪费了 80% 的预算**；
  加「部分返回」正是为了修这个。
- **不改召回排序**：本版只改「装多少」，不改「谁靠前」。⇒ 与召回质量相关的指标本版**不动**，
  也没有任何「召回变好了」的说法。

## §C 后果

- 装完什么都不动时：`_meta.json` 开始建档、低价值记忆开始移出活跃集、Episode 结束开始收口。
  ⇒ **已有工作区首次升级后索引与召回集会变化**（变瘦、变新），这是**有意的行为变化**，不是回归。
- 不变：契约面（`adr/0086`）不动、config 键不增不减、召回打分与渲染层不动、改码后本地 `build` 产出 `dist/`（v1.20.6 起不进 git）。
- 未验证（挂回原 ADR，**不得读成已解决**）：ADR-0067 的 `minHits` 链真机行为 · ADR-0068 的
  `runCompact` delta 真机行为 · 三件套在**真机规模**（8310 条）下的耗时未测 ·
  「默认开后索引变瘦多少」无量化（本版无 A/B）。
