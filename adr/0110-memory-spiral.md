# ADR-0110: 记忆螺旋 —— 收口成圈、材料成卡、平衡三律

- 状态：**已接受**（**设计与边界冻结**；实现在 `BACKLOG.md` V12，另计）
- 决定日期：2026-09-30
- 关联：**ADR-0038**（Episode 收口边界 —— 本 ADR 把「一次收口一个新文件」升级为「**同一张纪要连续收口**」）·
  **ADR-0106**（投影空间：`atoms/` `roles/` `affaires/` 权威 + `indexes/` 派生；五轴）·
  **ADR-0107**（hydrate：卡进枚举、不进排序）· **ADR-0095**（派生索引层：`.md` 才是权威）·
  **ADR-0072**（标签不得强于事实）· `reflection/`（反思螺旋：只产 `candidate`，不写回）
- 定位：**记忆的成长模型宪法**。回答「重复出现的东西怎么长成资产」「什么允许被改写」「改写凭什么被允许」。
- 触发：用户 2026-09-30 两问 ——「文件太多，读取效率是问题；一句话一个文件很浪费，也没有**像螺旋一样平衡进化背景材料**」+
  「**不要考虑工程量和历史数据，只要好的设计**」。

## 1. Context（先把问题定住：三条实测事实）

本机 `D:\project\dsh1\.shadow` 的真实读数（探针与读数落 `../.docs/fix/2026-09-30/atom-shape.ts` + `atom-shape.txt`）：

1. **不是 I/O 问题。** 语料 **466 条 / 307.9 KB**；Node **全量读完并解析 466 个文件 = 184–206 ms**（连跑三次）。
   SQLite 能省的正是这 0.2 秒 —— 而 ADR-0095 一期在 **8.2k 条**语料上把查询从 2753 ms 压到 68 ms。
   ⇒ **「文件太多 → 读取效率是问题」这条因果链在当前规模上不成立**（0.3 MB 不存在读取瓶颈）。
2. **是颗粒度与容器问题。** 11 个会话产出 466 条（**平均 42 条/会话，最多的一个会话 183 条**）；
   正文 **≤1 行的占 89.7%**；**82.8% 没有摘要**；文件名 / 标题 / 入口 slug **全是 `shadow`（零区分度）**；
   `roles/` · `affaires/` · `soul/` **三个容器层在本工作区全不存在**，`indexes/` 下只有 466 张与原子一一对应的便利贴。
3. **收口机制存在，却在真机上从未生效，且即使跑通也不产生「成长」。** ADR-0038 冻结的收口（`compact`）自 v1.15.85 起
   **默认开**，但它在本机：`-consolidated.md` **0 个**、`_meta.json` 里 `status: "compacted"` **0 个**
   （README 的默认开关表自己写着「ADR-0068 `runCompact` delta **真机未验**」）。
   更要紧的是**形态**：`ep-<slug>-consolidated.md` 是「**一个 episode 一个新文件**」——
   它把条数从「每回合」降到「每件事」，但**不产生任何越绕越厚的资产**。

⇒ 用户说的「螺旋」缺的不是机制，是**承载成长的容器**：今天 `> 背景/材料：` 只是一行**路径字符串**
（本机 44% 的条目有它），同一份文档在几十条原子里的引用**各自为政、永不进化**。

## 2. Decision

### 2.0 主轴 = 材料卡（用户 2026-09-30 拍板「同意推荐」）

螺旋**绕的是材料**：一份材料越用越厚。**纪要（一件 Affaire 的收口）是挂在材料上的一个面，不是主轴本身。**
⇒ **读侧第一入口先展开材料卡的「厚处」**（结论圈 + 它牵到的 Affaire），再逐层下钻到纪要与原子。
反面（本 ADR 明确不选）：以事件为主轴 —— 那样「背景/材料」仍然只是一行死路径，与用户原始诉求相反。

⚠ **主轴的代价（如实写下）**：以材料为主轴，检索的**主线是「哪份材料」**，「按事找」退为二级入口；
且 **`key` 的规范化一旦不稳，同一份材料会裂成多张卡**（卡越裂，主轴越碎）。⇒ `key` 必须有**唯一一份**规范化实现
（路径 → 绝对规范化 + 大小写/分隔符归一；非文件材料用报题 / DOI），且**迁移/改名要能并卡**（并卡 = 归档旧 key 的圈，不删证据）。

### 2.1 三层载体 + 两条不变量

| 层 | 载体 | 可写性 | 性质 |
|---|---|---|---|
| **事实层** | `.shadow/atoms/**` | **只追加，永不改写、永不删除** | source of truth（ADR-0003 / 0038 不变） |
| **成圈层** | `.shadow/indexes/affaires/<id>.md`（**当前圈**）+ `.shadow/indexes/affaires/<id>.history/<圈号>.md`（**归档圈**） | 当前圈**可被新一圈改写**；**归档圈永不修改** | 当前圈 = 派生（可重建）；归档圈 = 归档（只追加） |
| **进化层** | `.shadow/indexes/materials/<key>.md`（**当前圈**）+ 同目录 `<key>.history/<圈号>.md`（**归档圈**）· `.shadow/roles/<id>.md`（**仍是 source**，ADR-0106 §2.2 不动）· `soul/` 派生切片 | 仅在「确认」后改写（§2.4） | 跨任务沉淀的稳定结论 |

**落点为什么在 `indexes/`（与 ADR-0106 对齐的必然结果，不是随手挪）**：ADR-0106 §2.2 把 `atoms/` · `roles/` · `affaires/` 定为 **source**，
而**纪要与材料卡的正文是「会被逐圈改写」的派生件** ⇒ **不得占 source 位**，一律落 `indexes/`。
⚠ `affaires/<roleId>/<id>.md`（**成员指针**）**仍是 source、仍不改写** —— 本 ADR 只把「逐圈加厚的纪要正文」放进 `indexes/`。

**两条不变量（在本版细化后仍然成立）**：

- **不变量 A（原子不可变）**：任何层**不得**以「更可读 / 更省地方」为由删改原子。
- **不变量 B（派生可重建）**：**当前圈**（纪要 / 材料卡正文）必须能**仅凭原子重建** ⇒ **只有原子可以是「唯一一份」**。
  ⚠ **归档圈是例外、且必须显式声明**：`history/<圈号>.md` 记录的是「**我们当时是怎么想的**」，**不可重建**（不是关于世界的真相，是投影的历史）
  ⇒ 它按**归档层**纪律处置：**只追加、永不改写**。这样「可回退」（§2.4 律 3）与「派生可重建」两条**不互相打架**。
  螺旋**不是**把解释层升格为事实源（ADR-0038 的方向 A 仍不做）。

### 2.2 一圈收口 = 同一张纪要变厚（本 ADR 对 ADR-0038 的唯一形态修改）

收口的产物从「每 episode 一个新 `consolidated` 文件」改为「**同一件 Affaire 只有一张纪要文件，每收一次口加一圈**」
（正文落 `.shadow/indexes/affaires/<id>.md`，§2.1 的落点规则）：

- 纪要文件 = **当前圈**（最新结论 + 支撑它的原子指针）；
- `<id>.history/<圈号>.md` = 之前每一圈的**逐字快照**（**归档，只追加**）；
- 圈号**单调递增，不许跳号、不许覆盖**。

⇒ **文件数与「事的件数」同阶**，不再与「回合数」同阶（本机 11 个会话 ⇒ 纪要应在**十位数量级**，而不是 466）。

### 2.3 材料成卡：`背景/材料` 从「路径字符串」长成资产（**主轴**）

每份被引用的材料有一张**材料卡** `.shadow/indexes/materials/<key>.md`（`key` = 规范化路径 / 报题 / DOI；规范化实现**只此一处**，见 §2.0 的代价）：

| 卡上记什么 | 为什么 |
|---|---|
| **它对哪些事重要**（Affaire 指针） | 从「一份文档」变成「一份有履历的文档」 |
| **我们从它那里得到过什么结论**（逐圈追加） | 这是「螺旋加厚」的**正文** |
| **读到的是第几版**（源指纹） | 材料会变；不记版本，结论就变成无法复核的断言 |
| **哪些结论之间有冲突**（`contradiction`） | §2.4 律 2 的落点 |

**作为主轴，它同时决定读侧的第一入口**：`read_shadow` 无参 → 先列**材料卡的厚处**（结论圈最多 / 最近被用到 / 有未解冲突的），
由卡上的 Affaire 指针**下钻**到纪要，再由纪要指针**下钻**到原子。⇒ 「按事找」仍可用，但走的是**第二入口**。

⇒ 这正是用户要的「**像螺旋一样平衡进化背景材料**」：绕的每一圈都把「这份材料**对我们**意味着什么」写厚一层，
而不是每圈重抄一次路径。⚠ 材料卡只登记**被引用过的事实**，**禁止 LLM 补写**（`Evidence ≠ Interpretation`，ADR-0072 同族）。

### 2.4 平衡三律（螺旋每加一圈，必须**同时**过三道）

| # | 律 | 判据 | 防的是 |
|---|---|---|---|
| 1 | **新证据** | 这一圈必须带进**新的原子指针**（或新的材料卡证据）；**没有新证据 ⇒ 不写**，只更新指针 | 无脑追加（文件继续变多） |
| 2 | **不矛盾** | 新结论与上一圈、与 `soul` 冲突时，**显式记 `contradiction`**（谁与谁冲突、各自证据是什么），**不许静默覆盖** | 无脑改写（悄悄改掉历史结论） |
| 3 | **可回退** | 每圈留 `history/<圈号>.md`；**任意一圈可单独回放** | 成长不可逆 |

**「平衡」= 这三条同时成立**：不增（律 1 拦）、不乱改（律 2 拦）、不丢（律 3 保）。

### 2.5 谁有权改写进化层：确认闸（第四重平衡）

`reflection/` 今天只产 `candidate`、不写回 Identity。螺旋的第三圈沿用**同一条纪律**：

- `candidate`（模式抽取出的候选结论）**不得**改写材料卡与 soul；
- **`confirmed` 才允许**改写；
- `soul.json` 核心**仍须** `writeSoulCore` + H3gate（ADR-0106 §2.5，**不放宽**）。

⇒ 「证据不足时不进化」——这是「平衡」的第四层含义，也是本 ADR 与「LLM 自动总结一切」的分水岭。

## 3. Consequences

- **条数与「事」同阶**：纪要 ≈ 会话/事件数；材料卡 ≈ 被引用材料的去重数；**原子照旧全留**（Forget≠Delete）。
- **读侧第一入口变成材料卡**（§2.0 主轴）：`read_shadow` 无参 → **材料卡的厚处**（结论圈最多 / 最近用到 / 有未解冲突），
  再由 Affaire 指针下钻到纪要、由纪要指针下钻到原子；「按事找」退为第二入口。
- **source 位没被侵占**：`atoms/` · `roles/` · `affaires/<roleId>/<id>.md`（成员指针）**仍是 source**；
  本 ADR 新增的**全部是 `indexes/` 下的派生件 + 归档圈** —— 与 ADR-0106 §2.2 的划分一致。
- **可回放性增强而非削弱**：ADR-0038 的 `Replay must survive compaction` 继续成立，且多了 `history/` 这条**更强的证据链**。
- **ADR-0038 的六条边界一条不松**：Episode ≠ Atom · Compact ≠ Forget · Summary ≠ Reality · Closed ≠ Proven ·
  Replay 必须活 · 方向 A 不做（写侧仍只产原子，成圈是派生）。
- **与 SQLite 的关系不变**：ADR-0095 的 *SQLite MUST NOT become the authority for memory content* **照旧**；
  等条数回到千级、并且「扫目录」真的成为瓶颈时，才启用已实现的 sqlite provider。

## 4. Non-goals

- ❌ 以**事件**为主轴（本版定的是**材料**为主轴；纪要只是材料上的一个面 —— 见 §2.0）
- ❌ 把会被逐圈改写的正文放进 **source 位**：`affaires/<roleId>/<id>.md` **只放成员指针**，正文一律落 `indexes/`
- ❌ 让 `key` 规范化散成多份实现（那会让同一份材料裂成多张卡 ⇒ 主轴自己碎掉）
- ❌ 把权威搬进 SQLite（ADR-0095 的 MUST NOT 不变）
- ❌ 让 episode / 纪要反过来覆盖或替换原子（ADR-0038 方向 A）
- ❌ 为降条数牺牲可回放性
- ❌ 在纪要 / 材料卡里写评价性结论（「已确认最佳」一类 —— ADR-0038 §3 不变）
- ❌ LLM 补写材料卡或纪要正文（只登记被引用过的事实）
- ❌ 未经 `confirmed` 就改 `soul` / 材料卡
- ❌ 借「螺旋」引入日期目录树（ADR-0106 已废）或新的根名
