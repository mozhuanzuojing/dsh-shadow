# ADR-0097: 记录粒度 —— 「一次动作一个文件」降级为**审计流**，记忆以「含线索的批」为单位

- 状态：**已接受（方向）** · 实现随 `v1.19.0` 落地；**历史语料不改写**（见 §5）
- 决定日期：2026-09-21
- 关联：**ADR-0001**（投影文件树：权威 = 可读可编辑的纯文本）·
  **ADR-0003**（派生件不是 source）· **ADR-0049**（缺件不静默）· **ADR-0060**（多粒度检索）·
  **ADR-0095**（派生索引层 —— 与本 ADR **正交**：它治**读延迟**，本 ADR 治**写粒度**）·
  **ADR-**（目录级 sidecar / `scopedFs` 写入策略）
- 定位：**载体与粒度**决策。回答「**什么算一条记忆、它落成什么**」。
- 触发：用户对「一条记忆 = 一个文件」提出质疑（原话：「这个设计不是很好，重新思考」）⇒ 先量后改（§1）。

## 1. Context：先量（本工作区 `.shadow`，14,记忆文件，2026-09-21 实测）

| 指标 | 实测 | 说明 |
|---|---|---|
| 单文件大小 | 平均 **484 B** · 中位 **439 B** | ** < 512 B** ·  < 1 KB ·  < 4 KB |
| 盘上浪费 | 内容 6.62 MB，按 4 KB 簇约 **56 MB** | **≈ 是簇内碎片** |
| 样板占比 | 159,里 **99,（）是 `>` 溯源样板** | 正文（`- [时刻] …`）只 ****，空行  |
| 记录含金量 | ** 的记录「0 用户消息 且 0 决策」** |  无用户消息 ·  无决策 |
| 动作数 | 中位 **1** 个 · 平均 1.4 | ≤动作占 ****，≤2 占  |
| 目录扇出 | 单目录最高 **2,671** 个（2026-09-08） | 平均 1,/天 |
| 复制放大 | 一次整树复制 = 1.4 万次文件操作 | `v1.18.5` 清理掉的 133,文件 = 这份语料的 **副本** |

中位样本（`2026-09-07--134404-shadow.md`，439 B）：两行摘要 + 五行样板 + **一行正文** `- [13:44:04] [edit] 调用 edit`。

**病灶不是「一个文件」这个形态，而是把「观测层的最小粒度（一次工具调用）」直接当成了「记忆的落盘单位」**，
并给每条重复一份占  的溯源样板。`CONTEXT.md` 定义的记忆是「交互 + 决策 + 思维落点 + 背景/材料 + 用户提示」——
而上面这类记录里**一个要素都没有**，它是**审计流**，不是记忆。

**设计意图与实现断裂（本次才发现）**：`core/types.ts:23` 声称收口能带来「**File 少**」，
但 `core/forget.ts:37` 只把原子标成 `status="compacted"`，`.shadow` 下**没有归档目录** ⇒
原子**原地保留** ⇒ 实测 **11,原子 + 2,收口件**，**文件数一个没少**。
收口买到的是读侧噪声下降，**没买到它自己承诺的文件数下降**。

## 2. 被捆在一起的三件事，只有一件该动

| # | 决定 | 现状 | 本 ADR |
|---|---|---|---|
| ① | 权威 = 可读/可编辑/diff 的纯文本 | `.shadow/*.md` 是 source（ADR-） | **不动**（这是卖点，也是证据链的前提） |
| ② | **记录粒度 = 一次动作一条** | 捕获层直接产出「原子记忆」 | **改**（本文核心） |
| ③ | 落盘单位 = 每条一个文件 | 一原子一文件（②的放大器） | 由 ② 的修正**连带解决** |

## 3. Decision

**D1（记忆判据，可机械化）**：一批 `pending` 记录的组成决定它的落点 ——
**含 `user` / `decision` / `assistant`（思维落点）任一 ⇒ 记忆文件**（走既有路径，一字不改）；
**只有 `action`（fs/tool 回声）⇒ 审计流**。
判据**不需要新增字段**：`core/memory.ts:60` 的 `> 证据链：来源(动作·用户·agent·决策)` 已经把「这批里有什么」编码进去了，
「`来源(动作)` 孤零零一个」就是纯动作回声的充要标记（这也是将来那道门的判据）。

**D2（审计流落点）**：`.shadow/audit/<date>.jsonl`，**只追加**，一行一条 JSON，
字段 = 原本会进记忆正文的那些（`at` / `kind` / `text`（已 `sanitizeText`）/ `comp` / `agent` / `project`）——
**一字不丢**，只是不再各占一个 inode、不再各带一份样板头。
追加实现**复用**既有那一份（`query/observatory.ts:111-133` 的 `readText → 拼接 → writeText`，
它已处理「真实 fs 对不存在路径抛错」与「目录由宿主 `writeText` 的 `mkdir -p` 建」）⇒
抽成 `persistence/jsonl-append.ts`，两处共用（**判据收一处**：同一件事只有一份实现）。

**D3（读侧不受影响，已逐条证明）**：`persistence/files.ts:50` 只认 `^\d{4}-\d{2}-\d{2}$` 的目录 ⇒ `audit/` **整个目录不被枚举**；
`isMemoryFileName`（`files.ts:39-41`）只认 `.md` 且排除 `_` 前缀；`core/candidate/sqlite.ts:203` 用同一判据；
目录级 sidecar（`retrieval/abstract.ts:159`）只由**记忆**落盘调用 ⇒ `audit/` 不会长 `_abstract.md`。
⇒ 审计流不进 `_meta.json`、不进索引、不计 hits、无生命周期 —— 与 `.shadow/query-log/`、`shadow-index/` 同一层级（系统派生记录）。

**D4（不丢证据，但不是「完全没丢」）**：① 审计记录**本身落盘**（含 `改/读 <路径>` 原文与 `comp`）；
② 审计批的材料**折叠进下一条记忆**的 `背景/材料`（有界缓冲、逐 agent），避免「纯动作批读过的文件」从记忆层消失。
⚠ 折叠是**启发式**：若一个纯动作批之后再无记忆批，其材料只留在审计流里（文件在、可 grep，但不出现在任何记忆的 `背景/材料`）。

**D5（配置）**：`capture.echo: "audit" | "memory"`，**默认 `"audit"`**（= 本 ADR）。
`"memory"` 是旧行为的逃生口（每条回声一个记忆文件）。改默认值 ⇒ 按 `AGENTS.md` 重跑 `npm run sweep:timebomb`。

**D6（历史不改写）**：已有 **8,纯动作文件原地保留**（归档层不动，同 `adr/0049` 的分层纪律）。
一次性收口是**不可逆**操作 ⇒ **需用户单独拍板**，本 ADR 只给方案（§5）。

**D7（门，且只对起点之后生效）**：粒度门判「**记忆文件不得是纯动作回声**」（D1 的判据），
起点 = `2026-09-21`；起点之前的历史**豁免**并**打印边界**（同 `audit:docs` ⑤ 的「仪式起点」手法）。

## 5. 边界与未做（**别当已做完**；缺件不静默）

1. **审计流当前不被读侧消费**：不进 `_meta.json` / 索引 / hits / 生命周期。**v1.19.1 已部分收口** ——
   `read_shadow({debug:true})` 能读到它与它的材料（`persistence/audit-stream.ts`），但**没有**接进
   lineage/evidence 的聚合面（见 §7.2 ⚠）。
2. **材料折叠是启发式的**（D4 ⚠）：无后继记忆批时，材料只在审计流里（现由 §7.2 的 debug 面兜住可见性）。
3. **历史 8,文件的回收**：**v1.19.1 已做**（用户明示「回收」）——工具、备份、逐字不变量与独立对账见 **§7.1**。
   它之所以**不是**「改写归档」：只搬不写，且原始内容全量备份（可逆）。
4. **跨进程并发追加未测**：`read+concat+write` 只在**同一进程内**串行化（与 `query-log` 同一边界）。
5. **门的起点豁免**：起点之前的历史文件会被门**跳过**，所以「全仓记忆文件都不是纯动作」这句话**不成立**，
   成立的是「**起点之后**没有新的纯动作记忆文件」。
6. **门当前的覆盖是 0**（诚实登记，别拿它的绿当「粒度已经对了」）：起点是 `2026-09-21`，
   而语料里最新的日期目录是 `2026-09-20` ⇒ 门实测 **判定  · 豁免 14,**。
   它的覆盖**从起点之后的第一个日期目录起**才非零；今天它只证明「历史没有被改写」。
   （判据本身有标定：`tools/granularity-audit.selftest.ts` 的正/负对照 + 历史豁免控制 + 「不猜」控制。）
   **v1.19.1 更新**：§5.3 的回收做完之后，同一读数变成 **判定  · 豁免 5,**（剩下的全是「非纯动作」的记忆，
   它们只是**不需要判**，不是被判通过）—— 本门的覆盖仍要从起点之后的第一次采集才开始非零。

## 6. 与既有 ADR 的关系（本 ADR **不改**它们的正文）

- **ADR-0095 正交**：它用派生索引治**读**（全量扫 3.3–3.6 s → 目录令牌 4.7–5.7 ms），
  **不减少文件数、不减簇浪费、不减复制放大**。本 ADR 治**写**。两条都要有。
- **ADR- 守住**：权威仍是纯文本；审计流是**可读可 grep 的纯文本**，且**派生件永远不是 source**。
- **ADR-0049 由 D4 + §5 承担**：审计记录本身落盘，且缺口逐条写明、进 BACKLOG。
- **`CONTEXT.md` 的记忆定义**（交互 + 决策 + 思维落点 + 背景/材料 + 用户提示）**就是 D1 判据的来源** ——
  本 ADR 没有发明新定义，只是让落盘单位服从那个已存在的定义。

### 7.1 历史回收（`§5.3` 从「未做」变成「已做」）

- **工具**：`tools/granularity-reclaim.ts`（**默认 dry-run**，`--apply` 才动；判据与门共用
  `tools/granularity.lib.ts` —— 两处必须逐字同判，否则「门绿了但回收漏了一批」）。
- **执行结果**（本机 `D:\project\dsh1`）：**8,删除 · 13,动作记录进 
  `.shadow/audit/<date>.jsonl` · `_meta.json` 11,834 → 2, · 剩余记忆文件 5,423（= 预测值）·
  剩余纯动作记忆文件 0**。
- **它为什么不是「改写归档」**：只搬不写。三条硬证据 ——
  ① 每条记录的 `renderBodyLine(记录) === 原始正文行` 是**脚本内的中止条件**（任一不等即 `exit 1`，不做部分回收）；
  ② 原始文件**全量备份**（含头部）在 `vendor/.docs/fix/2026-09-21/reclaimed-pure-action-memories.jsonl`
     （8, / 5.4 MB，每行 `rel` + `sha256` + `content`）⇒ **可逆**；
  ③ 记录里带 `from: "<原始 rel>"` + `reclaimed: true` ⇒ 谁都能追回来源。
- **独立对账**（不信工具自报）：备份 8, `rel` / 声明 13, ↔ 审计流 **13, / 8,不同 `from`**，
  差集 **0**；随机抽 文件，逐个「从备份还原正文行 ↔ 审计流记录」** 命中**。
- **一处工具自身的缺陷（据实记录）**：备份默认路径第一版写成 `join(here,"..",".docs")` ⇒落到**仓库内**的
  `.docs/`，而 `.docs` **不在** `.gitignore`（`git status` 直接报 `?? .docs/`）⇒ 5.4 MB 备份差点被提交进仓库。
  已搬到 `vendor/.docs/fix/2026-09-21/` 并把默认值改成 `../../.docs/fix/<日期>`（注释写明这次踩坑）。
- **不碰**：`_index.md`（派生件；日期目录的令牌变了，下一次读自会重建）、合并件（`ep-`）、
  `query-log/`、`resources/`、任何非「纯动作」的记忆文件。

### 7.2 T21：审计流接读侧（**只到「可见可查」**，不越线）

  + `renderAuditStreamDiag`。材料 = `materials` 字段 ∪ 从 `改/读 <path>` 推断（回收来的记录两种都有）。
- **挂点**：`read_shadow({debug:true})` 的诊断区（`query/query.ts`）。**刻意不进召回正文** ——
  整个本 ADR 就建立在「审计流不是记忆」这条线上，把它塞进召回会把那条线抹掉。
- **三条判据的落地**：① 材料可从读路径取到（debug 行带出）✓；
  ② 审计流**仍不进** `_meta.json`/索引/hits（端到端测试里用 `listMemories` 断言 = 0）✓；
