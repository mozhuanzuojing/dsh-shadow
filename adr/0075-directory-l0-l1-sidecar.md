# ADR-0075: 目录级 L0/L1 sidecar —— 吸收 OpenViking 三条（D6 落地）

- 状态：**已接受（2026-09-11）**
- 决定日期：2026-09-11
- 关联 ADR：**ADR-0065**（吸收 OpenViking：三条可吸收项的来源，本 ADR 是它的**实现**）、**ADR-0003**（派生件不是 source）、**ADR-0042/0043**（LLM 不能制造关系 ⇒ 派生必须确定性）、**ADR-0049**（缺件不静默 ⇒ 写失败必须可见）、**ADR-0069**（投影必须跟得上源头）、**ADR-0071**（`listDir` 升序 ⇒「取第一个」= 取最旧，本 ADR 同坑）、**ADR-0074**（写入必须带会话策略）
- 关联待办：`../BACKLOG.md` 的 **D6**（本 ADR 结案它）；新开 **T9**（读路径收益未测）
- 版本：`1.15.35`

## Context

`adr/0065` 对 OpenViking 做了一手材料调研，结论是**三条可吸收**、且三条**都属 Projection（派生可重建）**，
故不违反 ADR-0003。`BACKLOG.md` 的 **D6** 记录了用户「按推荐」授权：**三条都做**，但当时**未实现**
（需新增一类派生文件、改 `_index.md` 定位、加漂移棘轮，属独立工作量）。本 ADR 落地它。

### 三条要吸收什么（引自 `adr/0065`）

| # | OpenViking 做法 | 本仓当时的缺口 |
|---|---|---|
| ① | **目录级** abstract + overview sidecar（每层目录都带 L0/L1，256 / 4000 字符上限） | 判断相关**必须先读记忆文件**，只能靠全局 `_index.md` |
| ② | **上层由下层确定性派生**（它的 L0 从 L1 正文里抽：H1 之后、首个 `##` 之前） | 本仓三层各自从原文派生 ⇒ 存在「同一条记忆的两层说法不一致」的可能，**且没有判据能发现** |
| ③ | 派生件**自报覆盖率与待处理变更**（它的 sidecar `freshness`：子项覆盖数 + `pending_child_changes`） | 单一源指纹答不了「这份摘要是**基于哪几个子项**得出的」 |

### 落地前必须先定的两件事（D6 记为「待定」）

1. **sidecar 放哪 / 叫什么**。实测 `persistence/files.ts` 的 `listMemories`（= 语料枚举器）行为：
   它只扫 `.shadow/<YYYY-MM-DD>/` 下的 `*.md`，且**只排除 `_index.md` 这一个名字** ——
   其余**任何** `.md` 都会被当成一条记忆（进索引、进召回、进计数）。
   ⇒ 若把 sidecar 放进日期目录，**必须**改枚举器的分类判据。
2. **谁是目录级 L1 的权威**。全局 `_index.md` 已存在；目录级 L1 是新的第二层。

## Decision

### 0. 选型（用户 2026-09-11 选定 **A**）

| 选项 | 结论 |
|---|---|
| **A（采）** `.shadow/<date>/_abstract.md` + 教 `listMemories` 跳 `_` 前缀 | sidecar 与它描述的目录**同址**（贴近 OpenViking「每层目录自带 L0/L1」）；`_index.md` 仍是**全局** L1，sidecar 是**目录级**、对**该目录**权威 —— 两层职责不重叠 |
| B（否） `.shadow/shadow-index/abstracts/<date>.md` | 零改枚举器，但 sidecar 与它描述的目录**分离**，「目录级」语义变弱 |
| C（否） 本轮不做 | —— |

**为什么改枚举器的判据而不是逐名列举**：原实现是 `n === "_index.md"` —— 那是**按名字**排除，
每加一个派生件就要记得回来补一句，而「忘了补」的后果是**静默污染语料**（本项目最常见的一类缺陷）。
改成**按 `_` 前缀**分类后，「派生物 vs 记忆」有了**唯一判据**，
与 ADR-0074 的 `scopedFs`、T5 的 `isAdmissibleClaim` 是**同一手法**（判据收一处）。

### 1. 层次与「每层只从下面那层派生」（② 的全部内容）

```
记忆文件（source，唯一事实源）
        │  deriveL1：确定性，只取可复核事实（条数/时刻跨度/入口/主题清单）
        ▼
目录级 L1 overview（≤ 4000 字符，写进 .shadow/<date>/_abstract.md）
        │  deriveL0：从 L1 正文确定性抽取（剥标题行、折叠空白、截断）
        ▼
目录级 L0 abstract（≤ 256 字符，同一文件）
        │  引用（不是再派生一遍）
        ▼
_index.md 的「目录摘要（L0 · 派生物）」段（最近 N 个目录）
```

**②的要害在「L0 是 L1 的函数」**：若 L0 也从记忆文件另抽一遍，就会出现「同一条记忆的两层说法不一致」——
而两层各自看都「没错」，**没有判据能发现**（这正是 ADR-0063/D5 那一族的形态）。
从 L1 抽 ⇒ 层间不一致在**构造上不可能**。测试 ② 直接断言这条不变量。

### 2. 三条硬边界（越界会污染 source，写在模块头）

1. **派生件不是 source**（ADR-0003）：sidecar 可整份重建，删掉不丢任何事实。
2. **所有输入显式传入**：`core/abstract.ts` **不读时钟、不读随机数、不读 fs** ⇒
   同输入必得**逐字节相同**输出（测试 ① 锁住）。这也是 ② 可验证的前提。
3. **命名必须 `_` 前缀**：由 `listMemories` 按前缀分类（测试 ⑤ 锁住）。

### 3. ③ 覆盖率自报：写下它，**但不信它**

`renderSidecar` 写入显式的 `covered: N` / `pending: M` 行（**可逆向解析**，不靠模糊匹配）。
`sidecarDrift` 的存在意义是**独立重算**这三个判据，而不是相信 sidecar 的自报：

| 判据 | 检测什么 |
|---|---|
| L1 逐字节 == 由当前源重新派生的结果 | sidecar **落后于源头**（ADR-0069 同族） |
| L0 == `deriveL0(sidecar 自己的 L1)` | L0 被**单独改过** ⇒ 层间已漂移 |
| `covered` == 实际条数 且 `pending` == 0 | 自报覆盖率**与事实不符** |

**正对照（ADR-0062 §2 纪律：先证工具会报警，再用它）**：测试 ③ 构造三种坏件
（源头多一条 / L0 被单独改 / 坏文件）并断言全部被抓到 —— 否则「0 条漂移」可能只是检测器不工作。

### 4. 默认**开**（与 `projectionStore` 默认关**不同**，理由写清）

1. 它是**派生物**（ADR-0003），可整份重建、删掉不丢事实；
2. 写入次数**有界**：每个**日期目录一份**，不是每条记忆一份（O(#dates) 而非 O(N)）；
3. **它就是 D6「三条都做」的产物** —— 若默认关，等于**又一次「写好了但从不执行」**，
   恰是本仓 **T1/T4 刚清理干净**的那一类（`countInconsistency` 的教训）。

`abstracts.enabled: false` 可关；`abstracts.showInIndex`（默认 3，0 = 不在 `_index.md` 里列）。

### 5. 读路径存在（不做死代码）

写完 sidecar 后，`_index.md` 追加「目录摘要（L0 · 派生物）」段，列出**最近 N 个目录**的 L0。
**顺序纪律**：先写 sidecar **再**写 `_index.md` —— 反过来会让索引指向一份写失败的摘要
（写失败的目录**不列入** `_index.md`）。这条读路径是 `read_shadow()` 无参路径的一部分，
故 sidecar 不是死代码（测试 ⑥ 端到端断言 `_index.md` 含该段）。

## Alternatives Considered

| 备选 | 否决理由 |
|---|---|
| sidecar 放进 `.shadow/shadow-index/`（选项 B） | 零改枚举器，但 sidecar 与它描述的目录分离 ⇒「目录级」语义变弱，且不符 OpenViking「每层目录自带 L0/L1」的形态 |
| 逐名列举排除（继续 `n === "_index.md"` 并补一句） | 每加一个派生件都要记得回来补；「忘了补」的后果是**静默污染语料**。改成前缀判据后该风险消失 |
| L0 直接从记忆文件派生（与 L1 并列） | 会出现「同一条记忆两层说法不一致」且**无判据可发现** —— 正是 ② 要消除的 |
| sidecar 每条记忆一份（而非每个目录一份） | 写放大 O(N)；且 OpenViking 的模式明确是**目录级**（"不为每个文件建"） |
| 默认关（与 `projectionStore` 一致） | 会让 D6 的产物**从不执行** ⇒ 重蹈 T1/T4 清理的那类「写好了没接线」。★但需诚实标注：本决定的**代价**是新增一类写入，真机规模未测（见「负」） |
| 让 `sidecarDrift` 读 fs（而非纯函数） | 纯函数才能在棘轮测试里构造坏件；读 fs 会把「检测器」与「被测对象」耦合，且违背边界 2 |
| 用 sidecar 改变召回排序 | **本轮不做**：那是检索层改动，需评测（新开 **T9**），不该夹在「补一层派生件」里 |

## Consequences

### 正

- **目录级 L0/L1 存在**（①）：读 `_index.md` 即可看到最近目录的摘要，不必先读记忆文件。
- **层间漂移在构造上不可能**（②）：L0 = f(L1)，且该关系有测试与棘轮判据（`sidecarDrift`）。
- **派生件自报覆盖率**（③）：`covered`/`pending` 是显式行，被独立重算。
- **枚举器的分类判据收敛到一处**（`_` 前缀）：以后再加派生件**不必**记得回来改枚举器。
- 三条不变量（纯函数 / 层间派生 / 前缀命名）都有测试锁，且**含正对照**。

### 负 / 已知边界

- **新增一类写入**：每次索引重建为每个日期目录写一份 sidecar。**代价有界但未在真机实测规模**
  （本测试只用 1–2 条记忆）⇒ 见 **T9**。
- **读路径收益未测**：本轮只做到「`_index.md` 引用 L0」，**未改检索排序** ⇒
  「sidecar 是否真的改善相关性判断」**没有评测**。**不得表述为已验证**（新开 **T9**）。
- **存量回填未做**：旧目录的 sidecar 要等各自索引重建才生成（不做一次性全库回填）。
- **L0 抽取质量未评**：它只是 L1 的确定性首段（**不含判断** —— 判断属读侧，ADR-0042/0043），
  故 L0 读起来像「清单摘要」而不是「结论」。
- **`pending` 恒为 0 是构造性的**：本实现里 sidecar 与 `_index.md` 用**同一份 `recs`** 派生 ⇒
  不可能落后。故 `pending` 字段当前**只在棘轮/构造坏件时有意义**（它是对**未来**增量场景的预留）。
  **这一点必须诚实说明**，否则会让人以为「pending 会真实报警」。
- 与 `projectionStore` 的策略不一致（一个默认开、一个默认关）：理由见 Decision §4，
  但这是一处**需要读者留意的口径分叉**。
