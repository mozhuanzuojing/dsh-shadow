# ADR-0109: 复杂度预算门 —— 用「文件行数 + 热点棘轮」这两个文本代理（`T13` 后半）

- 状态：Accepted（`v1.21.29`）
- 依据：`adr/0078-hl-mem-third-read-clone.md` D3（hl_mem 的 `scripts/check_complexity_budget.py` 16 KB +
  `complexity_budget.json`，口径是「本期每个热点上限**只能下调**」）；
  `BACKLOG.md` `T13` 后半；`AGENTS.md` 自己的约定「文件小而专注（200–400 行典型，≤800）」。

## Context

`T13` 前半（`v1.15.41`）把**分层方向**做成了门（`tools/audit-layers.ts`）。后半「复杂度预算」当时**没做**，
理由写在台账里：**本仓没有可用的 AST**。

本轮把这条理由重新量了一遍，仍是同一个结论：`package.json` 的 `typescript@7.0.2` 是 **native(Corsa) 移植**，
包根 `.` **只导出 `version`**（连 `ScriptTarget` 都没有），AST API 在 `typescript/unstable/ast` 这类 unstable 子路径
（同 `tools/audit-layers.ts` 的方法边界）。
⇒ hl_mem 那套「行数 / 参数数 / 函数体行数」里，**只有「行数」能可靠地量**。

另一条**必须先量再定**的东西是存量（`T13` 前半的教训：**表定错了，门当天就是红的 ⇒ 假闸门**）。

## Decision

### 1. 判据对象：两个**文本代理**，各自声明它代理哪种风险

| 代理 | 代理的风险 | 判据 |
|---|---|---|
| **文件行数** | 单文件过长 ⇒ **接手成本**（读一个文件要滚动多久） | **硬上限 800 行**（本仓 `AGENTS.md` 自己写的上限） |
| **热点行数（棘轮）** | 已经很长的大文件**继续膨胀** | 行数 ≥ **300 行**的文件进基线，**只能下调** |

**刻意不判**：「圈复杂度 / 参数个数 / 函数体行数」（无 AST，写不了不假装能判）、
「单文件导出数」（它是接口面，不是复杂度；且本仓 `core/types.ts` 有 26 个导出 —— 那是类型桶，判它只会制造噪声）。

### 2. 棘轮三分类（**与 `audit-wiring` 的棘轮刻意不同**）

- **上涨**（已记录的热点行数变大）⇒ **违规**（这是退化信号）。
- **新热点**（首次跨过阈值）⇒ **记账，不算违规**（否则每加一个大文件就红 = 假闸门）。
- **退出热点**（降到阈值下 / 已删）⇒ **提示收紧基线，不算违规**（降下去是好事，不该罚）。

两处「不算违规」**必须打印**（不打印＝静默放过，ADR-0049）。
（`audit-wiring` 的棘轮把「桶消失」判违规是对的 —— 那里的桶是**缺陷类别**，消失可能是工具坏了；
这里的桶是**文件**，消失的正常解释就是改小了。**同一形状、不同语义 ⇒ 判据不复用**。）

### 3. 防假绿：**扫到的文件数**健康门

本门的默认结论是「合规」。若根目录写错 / 遍历坏了，扫到 0 个文件也是「没有超限文件」⇒ **假绿**。
故基线里记 `scanned_files`，本次扫到的数**低于其 90%** 即**拒绝出读数**（exit 2）。
（同族：`eval` 的 `min_corpus_files`、`audit-wiring` 的「生产语料为空 ⇒ 拒出 0 线索读数」。）

### 4. 范围（**明确边界，不是漏掉**）

- **判**：产品面 —— `index.ts` + 源码目录（`core/` · `query/` · `persistence/` · `epistem`… 实测 **219** 个 `.ts`）。
  实测存量：最长 **587 行**（`core/toolset/index.ts`）、**10** 个热点（≥300 行）。
- **不判** `test/` 与 `tools/` —— 数字已量、写在这里备查：
  `test/recall-attribution.test.ts` **4546** 行（行为测试的单文件长度由覆盖面决定）、
  `tools/retrieval-eval.ts` **629** 行（工具面单文件）。
  把它们纳进来，硬上限**当天就红**（1 个文件 > 800）⇒ 又是假闸门。

## Alternatives Considered

1. **引入 AST（`typescript/unstable/ast` 或自写解析器）** —— 否。unstable 子路径无稳定性承诺，
   且为一个「行数级」的门引入编译级依赖不划算；本仓对工具最小的诉求是**可离线、零依赖**。
2. **用「导出数」代替行数** —— 否。见上表：它量的是接口面，会误伤类型桶（`core/types.ts` 26 个导出）。
3. **给所有文件都上棘轮（不只热点）** —— 否。任何**正常的功能增加**都会让文件变长 ⇒ 门天天红 ⇒ 被绕过。
   hl_mem 的形状本来就是「**热点**的预算只能降」。
4. **把 `test/` 纳入并给 4546 行那个文件做祖父豁免** —— 否。祖父豁免是「把已知违规写进基线」，
   会让「基线」同时承载两种语义（预算 vs 豁免），本项目宁可**明确划出范围**并**公开被排除的数字**。

## Consequences

- **正**：`AGENTS.md` 里「文件小而专注」第一次**有门**（此前只是散文）；热点膨胀会被抓住并指名。
- **负 / 已知边界**：
  - 判据是**文本代理**，不是真复杂度：一个 500 行但结构清晰的编排文件与一个 500 行的面条代码被判成一样；
  - **行数会因注释/格式变动而抖动**（本仓注释密度高）⇒ 棘轮上涨时**先看是不是只加了注释**；
  - **新热点不拦**：本门只能保证「已长的别更长」，不能阻止「长出一个新的 799 行文件」
    （硬上限拦得住 >800，拦不住 799）；
  - **范围外**（`test/`、`tools/`）**不判**，其数字只在本 ADR 里留档，会腐烂 —— 读它们时以现算为准。
