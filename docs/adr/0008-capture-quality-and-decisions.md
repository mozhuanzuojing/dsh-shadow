# ADR-0008: 采集质量与决策抽取

- 状态：已接受（v2.0-dev）
- 日期：2026-10-28
- 关联：ADR-0003、ADR-0004
- 定位：让 atom 真的能回答「为什么」。

## Context

v1 真实语料 168 条中 160 条入口 = `shadow`、151 条正文 ≤1 行、仅 33 条有摘要；决策里出现「保留前 600 字）」这类截断碎片。

## Decision

- **入口**：只取 fs 观察到的源路径域（`component`），排除 `.shadow`/空/`shadow`；无源路径时用项目名（workspace basename），绝不用 `shadow`。
- **决策**：只收 (a) 用户消息分类为 decision（选择/范围/锚点，含 `改成/改为/换成`）与 (b) goal/changed；助手消息不自动抽决策（避免碎片）。理由只取原文「因为/由于/…」，不补写。
- **摘要**：确定性兜底（首条用户消息 > 目标 > 首条动作 > 决策），默认 `auto` 即确定性；`off` 时明确不写。
- **披露**：`> 覆盖：N 条事件`；材料 ≥12 条时写「已截断到 12 条」；长消息写「已截断」。
- **项目/Agent**：线索头写 `> 项目`、`> Agent`，支持跨项目隔离。

## Consequences

- 入口分布可区分；决策可读；摘要不再依赖 LLM 可用性。
- 决策抽取仍可能误判，需用真实语料抽样评估（Phase 5）。

## Non-goals

不引入 LLM 补写理由/摘要；不改写 v1 旧 atom。
