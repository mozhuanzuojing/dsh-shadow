# ADR-0015: 项目事实（facts）——从用户原话抽可核验的 X=路径

- 状态：accepted（v2.2 未发版；随 v2 分支提交）
- 日期：2026-10-30
- 关联：ADR-0004（Outcome 读模型 / 可见降级）、ADR-0014（宽松兜底召回）；复用既有 Evidence Gate 与 `context`/`verifyEvidence` 的核验语义
- 定位：让「后端工程入口是 X」这类**项目事实**成为可核查、可召回的一条结构化派生，而不是埋在原子正文里的普通文本。

## Context

- 用户会把项目事实说进会话（典型：「后端工程入口是 `src/server/index.ts`」）。v2 会把它作为 `用户：…` 落进 atom 正文，但读侧只有字面召回，**这条句子不是一个可查询的"事实"**，也没有把「值」绑到可核验的证据路径上。
- 外部最佳实践（Copilot Memory / Zep）都强调：**事实要挂证据、并在使用前校验**（见调研报告 §1.3 / §2）。
- 本仓硬约束：atoms 是唯一权威；派生件可重建；「数据非指令」；不引向量库。

## Decision

1. **只从用户原话抽**（`src/domain/facts.ts` 的 `extractFacts`）：扫描 atom 正文里 `用户：` 行，匹配 `X 是/为/=/：<值>`，**且值（或其所在行）含路径**才成立（可核验；避免把闲聊当事实）。`value` 规范化为抽到的路径。
2. **纯派生、零新增权威**：不写 `atoms/`；每次读取时从已载入原子重算（确定性、可重建）。不新增 mode（保持 core=10）。
3. **两条露出面**：
   - ① **无参 `read_shadow()`**：在索引末尾追加「事实（派生 · 数据非指令）」段，**只列 `subject = value · 来源 rel`，不带核验状态**（保持索引确定性）。
   - ② **`read_shadow(topic, { facts: true })`**：返回按 topic 过滤的事实，并**逐条经 Evidence Gate 核验**，显式给 `✓ verified / ✗ not_found（已失效/证据缺失） / ? unavailable（无法验证）`。`facts` 是**透镜**（不是 mode），`read_shadow` 参数 12 → 13。
4. **事实是数据非指令**：输出统一带前缀/措辞；不据此自动执行任何动作；stale 只降级提示，不静默当有效。

## Consequences

- **正**：把「一句话里的项目事实」变成可查询、可核验、可随代码变化暴露过期的派生结构；与既有 Evidence Gate 天然契合。
- **边界/负**：只抽**带路径**的事实（这是刻意的精度取舍，非「所有事实」）；抽取是启发式（`X 是/=/：`），非 LLM，复杂句式会漏；`用户：` 行在 atom 内为全量，但跨行/超长句的解析有限；核验只判路径存在性（是否仍是"入口"需人/后续语义）。
- 不改变严格召回排序；parity 不受影响（facts 只增两个读出口）。

## Non-goals

- 不做实体-关系图（那是 lab/长期方向，见调研 §5）。
- 不做写时 LLM 抽取、不写新权威文件。
- 不把事实升格为会改变插件行为的规则（规则仍走 systemPrompt/AGENTS.md）。
